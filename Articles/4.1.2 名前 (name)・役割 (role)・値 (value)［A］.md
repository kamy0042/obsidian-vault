# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- 支援技術がコンテンツにあるユーザインタフェース コントロールの状態に関する情報を収集し、有効化（又は設定）及び最新の状態を保つ
    - 特に重要なユーザインタフェース コントロールの状態
        - フォーカスを持つかどうか
            - コントロールのフォーカス状態は、プログラムによる解釈が可能であり、フォーカスの変化に関する通知は、ユーザエージェント及び支援技術に送られる
        - チェックボックス又はラジオボタンが選択されているかどうか
        - 折り畳み可能なツリーやリストが展開されている又は折り畳まれているかどうか
- ユーザインタフェース要素が仕様に準じて使用される場合、自然とクリアできる
    - カスタムコントロールが作成される、又はインタフェース要素が通常とは異なる役割及び／又は機能を持つように（ソースコード又はスクリプトで）プログラミングされている場合、コントロールが支援技術に重要な情報を提供し、支援技術によってコントロールされることを、それら自身ができるように保証する追加の手段を取る必要がある
- すべてのユーザインタフェース コンポーネントに対して、プログラムによる解釈が可能な名前を要求する
    - 名前は、可視であっても、不可視であってもよい
        - 名前がラベルとして識別される場合、名前は可視でなければならない
- すべてのユーザインタフェース コンポーネントに、役割、状態、及び値の情報を提供することで、例えば、スクリーンリーダー、画面拡大ソフトウェア、及び音声認識ソフトウェアなどの、障害のある利用者が使用する支援技術との互換性を保つことが可能になる

# **どう実装したらこの達成基準を守れるか？**

エンジニア

### セマンティックなHTMLで実装する

- 標準的な HTML のフォームコントロール及びリンク要素を用いることで自然と達成される
    - フォームの場合は`label`要素との関連付け等も必要
    - その場合`label`要素でラップするよりも、`id`と`for`属性を利用した方が良さそう
    - [https://www.tpgi.com/should-form-labels-be-wrapped-or-separate/](https://www.tpgi.com/should-form-labels-be-wrapped-or-separate/)
    - `// 環境によっては関連付けが行われない
<label> Email address <input type="email">
</label>
// 関連付けが行われる
<label for="emailForm">Email address</label>
<input type="email" id="emailForm">`
- セマンティックなHTMLでマークアップしておけば、支援技術はアクセシビリティAPIを利用して、役割 (role)、名前 (name)、状態 (state)、値 (value) といった適切なアクセシビリティ情報を抽出できる

### 可視ラベルを利用できない場合の対応

- `label`要素の代替として`title`属性を使用する
    - この達成基準は可視/不可視を問わないため、title属性を利用することでもクリアできる
    - 支援技術を含むユーザエージェントは`title` 属性を読み上げ可能
- `aria-label`を設定する
    - 可視のラベルが存在しないが、コンテキストと視覚的な外観によってコントロールの目的が明確になっているような場合、アクセシブルな名前を提供するために`aria-label`を利用できる
    - 例：アイコンボタン等
- `aria-labelledby`を利用する
    - ページ上のテキストをアクセシブルな名前として利用したい場合、`aria-labelledby`による関連付けを利用できる
    - `<input name="searchtxt" type="text" aria-labelledby="searchbtn">
<input name="searchbtn" id="searchbtn" type="submit" value="Search">
<p>Please select the <span id="mysldr-lbl">number of days for your trip</span></p>
<div id="mysldr" role="slider" aria-labelledby="mysldr-lbl"></div>`
- ちなみに、`label`要素を可視要素として代替したいときは隣接するボタンのラベルを利用できる
    - [https://chatwork.atlassian.net/l/cp/owSJwn7M](https://chatwork.atlassian.net/l/cp/owSJwn7M)

### iframeにtitle属性を設定する

- 埋め込みコンテンツの内容を`title`属性で正確に説明する
- `title`属性がない場合、埋め込みコンテンツが何であるかを特定するために `<iframe>` の内容に移動しなければならない
- 達成方法に記載されている`frame`要素は現在非推奨のため利用不可

```plain text
<iframe
  title="Wikipedia page for Avocados"
  src="https://en.wikipedia.org/wiki/Avocado"></iframe>
```

### UIを独自実装する場合

WAI-ARIAを用いて名前 (name)・役割 (role)・状態 (state)をユーザーエージェントに伝える。

この対応を行う場合、キーボード操作や状態の通知など、roleに期待される挙動も同時に実装しなければならない。

- name
    - `aria-label`や`aria-labelledby`によってアクセシブルな名前を与える
- role
    - `role`属性を用いて要素のロールを定義する
    - [https://www.w3.org/TR/wai-aria/#role_definitions](https://www.w3.org/TR/wai-aria/#role_definitions)
- state
    - WAI-ARIA ステート及びプロパティ属性を使用することで、ユーザーエージェントがUIの状態を把握できる
        - チェック状態、開閉状態、フォーカス状態など
        - name,role,valueには該当しないが、UIの状態を通知するためには対応が必要
    - [https://www.w3.org/TR/wai-aria-1.1/#state_prop_def](https://www.w3.org/TR/wai-aria-1.1/#state_prop_def)
