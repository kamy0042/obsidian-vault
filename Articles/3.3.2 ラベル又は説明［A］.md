# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- ユーザーに入力を要求する場合は、期待される入力データが何なのかをユーザーが知ることができるようにフォーム内のコントロールを特定する説明又はラベルを提示する
    - 重要な手がかりおよび説明文を提供する
        - 情報または指示が多すぎると、少なすぎる場合と同じくらい有害になることもある
        - 利用者の混乱を最小限に抑えて、必要以上のナビゲーションを提供することなく、利用者がタスクを完了するために十分な情報を提供する
    - この達成基準の意図は、障害のある利用者に役立つ重要な手がかり及び説明文を提供すること
- 提示例
    - 利用者に選択肢を提供するラジオボタン、チェックボックス、コンボボックス、又は類似のコントロールの場合、利用者が実際に何を選択しているかをわかるように、それぞれの選択肢に適切なラベルが存在しなければならない
    - 特に一般的なフォーマットではない場合又は正しい入力のための特定のルールがある場合は、説明文又はラベルで、データ入力欄のデータフォーマットを明示してもよい
    - 特に説明が長く詳細である場合は、個々のコントロールがフォーカスを受け取ったときだけそのような説明文を利用者が利用できるように作ることをコンテンツ制作者は選択してもよい

## **例外**

デザイナー エンジニア

- ラベル又は説明が正確にマークアップされる、識別される、又はそれぞれのコントロールに関連付けられることを要求しているわけではない
    - 上記については、[1.3.1 情報及び関係性［A］](https://chatwork.atlassian.net/wiki/spaces/BRDG/pages/3646619782)で個別に扱われている
    - 達成基準 1.3.1に失敗していても、この達成基準には合格している場合がある
- フォームのコントロール及び入力欄にアクセシブルな名前 (accessible name) 又は説明を提供するための代替方法が使用されているかどうかは考慮されない
    - 上記については、4.1.2 名前 (name)・役割 (role)・値 (value) で個別に扱われる
    - 達成基準 4.1.2に合格していても、この達成基準に失敗していることもある
- この基準は、データ入力に関連しないリンク又はその他のコントロール（展開／折りたたみウィジェット、類似のインタラクティブなコンポーネントなど）には適用されない
- この達成基準では、データ入力及び送信のための、コントロール及び入力欄にラベルをつけることが求められているが、これらのラベルが十分に明確で説明的であるかどうかは、[https://waic.jp/translations/WCAG21/Understanding/headings-and-labels.html](https://waic.jp/translations/WCAG21/Understanding/headings-and-labels.html)で個別に扱われる

# **どう実装したらこの達成基準を守れるか？**

エンジニア

- インタラクティブなUIに対して、その目的を特定可能なラベルを提供する
    - ラベルを提供する際は、ラベルとフォームの関係性を予測できるように配置する必要がある
- かつ、以下のいずれかの方法で説明を提供する

### フォームの説明手段

- 必須項目
    - label 要素又は legend 要素のテキストに「必須」だと明記する
    - 入力が完了していない必須項目を特定するために、テキストによる説明を提供する
    - フォームの先頭で必須項目について説明する
- フォームの目的
    - aria-describedbyで説明文とフォームを紐づける
    - aria-labelledby を用いて複数のテキストを繋げて一つのラベルとして扱う
        - [https://www.w3.org/WAI/WCAG21/working-examples/aria-labelledby-time-out-input-concatenated-label/](https://www.w3.org/WAI/WCAG21/working-examples/aria-labelledby-time-out-input-concatenated-label/)
        - 複数に分割されたテキストを繋げ、“Extend time-out to 20 minutes“ とラベリングされている
- フォームのグループ化
    - 関連するフォームコントロールを特定するために、グルーピングロールを使用する
        - [https://www.w3.org/WAI/WCAG21/working-examples/aria-grouping-multipart-fields-ssn/](https://www.w3.org/WAI/WCAG21/working-examples/aria-grouping-multipart-fields-ssn/) `<div role="group" aria-labelledby="ssn1"> <span id="ssn1">Social Security#</span> <span style="color: #D90D0D;"> * </span> <input size="3" type="text" aria-required="true" title="First 3 digits" />- <input size="2" type="text" aria-required="true" title="Next 2 digits" />- <input size="4" type="text" aria-required="true" title="Last 4 digits" />
</div>`
        - １つの入力欄で扱う方がよさそう
    - fieldset 要素及び legend 要素を使用してグループ化し、目的を説明する
        - `<fieldset> <legend>The play <cite>Hamlet</cite> was written by:</legend> <input type="radio" id="shakesp" name="hamlet" checked="checked" value="a"> <label for="shakesp">William Shakespeare</label><br /> <input type="radio" id="kipling" name="hamlet" value="b"> <label for="kipling">Rudyard Kipling</label><br /> <input type="radio" id="gbshaw" name="hamlet" value="c"> <label for="gbshaw">George Bernard Shaw</label><br /> <input type="radio" id="hem" name="hamlet" value="d"> <label for="hem">Ernest Hemingway</label><br /> <input type="radio" id="dickens" name="hamlet" value="e"> <label for="dickens">Charles Dickens</label>
</fieldset>`
- フォーマット
    - 期待されるデータ書式及び入力例を提供する
        - `<label for="date">Date (dd-mm-yyyy)</label>
<input type="text" name="date" id="date" />`

### 推奨されない達成方法

- テキストフィールドの目的をラベル付けするために隣接するボタンを用いる
    - 以下の場合、ボタンはテキストフィールドに対するラベルとしての役割も果たす
        - テキストフィールド上である機能を実行するボタンがある
        - ボタンは明確にラベル付けされている
        - ボタンとテキストフィールドと隣り合って表示されている
- **この方法は「最後の手段」として考え、その他の達成方法をページに適用することができないときだけに用いる**
- 「視覚で捉えられる関係性」と「音声の読み上げ順序」に依存しているので、推奨される状態ではない
