# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- コンテンツのすべての機能は、<u>個々のキーストロークに特定のタイミング</u>を要することなく、キーボードインタフェースを通じて操作可能である
    - 利用者が短時間のうちに複数のキーストロークを繰り返すもしくは実行する必要がある状況
    - 又はキーストロークが記録される前に長い間キーを押し続けなければならない状況
- 可能な限り、コンテンツをキーボード又は（代替キーボードが利用できるような）キーボードインタフェースで操作ができるようにする
    - 目と手の協調運動を必要とするマウスのようなデバイスを使用できない全盲の人も、代替キーボード又はキーボードエミュレータの機能を果たす入力デバイスを使用しなければならない人も、マウスを使うのが非常に難しいと感じ、通常はキーボードを使用している手に震えのある人も、操作できる
    - ロービジョンの人はポインタを目で追うことが困難なことがあり、キーボードからソフトウェアを操作できる場合、ソフトウェアの使用がはるかに容易になる（又は、単に使えるようになる）
- ユーザーの入力時、OSのキーボードアクセシビリティ機能が利用される可能性を考慮することが期待される
    - 例
        - 修飾キーをロックする機能が有効になっていても、コンテンツが機能し、修飾キーロックと衝突して予期しない結果を生まないイベントを送信するようにすべき
- 通常スタイラスペンで操作する PDA 機器（オプションで取り付け可能なキーボードがある）
    - キーボードのみのアクセスで動作するように設計されているので、ウェブコンテンツは操作可能

## **例外**

デザイナー エンジニア

- 根本的な機能が利用者の動作による終点だけではない軌跡に依存する入力を必要とする場合
    - キーボードから合理的に操作できないものを区別するために含まれている
- 過度のキーストローク数を必要としない既知の方法でキーボードから実行できないポインティングデバイスで行われる細かな入力
    - 軌跡に依存した入力を要する機能
        - 自由な手描き
        - 水彩画
        - 障害物コースを通るヘリコプターの飛行
    - 以下は（軌跡に依存した入力を必要としないので）例外に**ならない**
        - 直線や規則的な幾何学的図形を描く
        - ウィンドウのサイズを変更する
        - ある位置へオブジェクトをドラッグする（その位置への軌跡に関係がない場合）
            - Chatworkのファイル送信のドラッグはこちらにあたるので、キーボード操作<u>ができなくてはいけない</u>
- マウスキーの使用（例外というか、対象外）
    - キーボード操作に当たらない
- 水彩画を描くプログラム
    - 筆の動きが速度及び持続時間によって変化する
- ヘリコプター飛行訓練シミュレータ
    - シミュレータの性質上、模型ヘリコプターの動作をリアルタイムで教えるものである

# **どう実装したらこの達成基準を守れるか？**

エンジニア

### セマンティックなマークアップを行う

- ユーザエージェントは、HTML のフォームコントロール及びリンクのキーボード操作を提供している
- つまり、インタラクション可能な各要素に対して適切なタグを用いればキーボード操作が可能になっている
    - 詳しく知りたい方はリファレンスを読んでください
        - [https://www.htmq.com/](https://www.htmq.com/)
- 例： ボタン
    - `// HTMLでは複数の方法でボタンを実装できるが、それらは全て「プッシュボタン」というroleに位置付けられる
// button 要素内の "save" というテキストが名前 (name) となる
<button>Save</button>
// 'value' 属性を用いて "Save"、"Submit"、"Reset" という名前 (name) を指定している
<input type="button" value="Save" />
<input type="submit" value="Submit" />
<input type="reset" value="Reset" />
// 'alt' 属性を用いて "save" という名前 (name) を指定している
<input type="image" src="save.gif" alt="save" />
// 'title' 属性を用いて "save" という名前 (name) を指定している
<input type="image" src="save.gif" title="save" />
// 'alt' 属性と 'title' 属性の両方を指定する場合、 'alt' 属性が名前 (name)となる
<input type="image" src="save.gif" alt="save" title="save the file" />`

### キーボードがトリガーとなるイベントハンドラを提供する

- 非キーボードの UI イベントによって引き起こされるすべてのイベントハンドラを、キーボードベースのイベントとも関連付ける

### **イベント対応表**

| **マウス向け** | **キーボード向け** |
| --- | --- |
| mousedown | keydown |
| mouseup | keyup |
| click | keypress |
| mouseover | focus |
| mouseout | blur |

### 事例

- ドラッグ＆ドロップ機能
    - 利用者がキーボードのみを用いて写真を選び、リスト内の適切な場所でアイテムを「切り取り」及び「貼り付け」できる
- 並び替え機能
    - 質問事項をドラッグで動かして調査票を作ることができるウェブアプリケーションには、テキストフィールドの付いた質問リストがあり、利用者が質問番号を入力することによって、必要に応じて質問事項を並び替えることができる
- マウスオーバー
    - onmouseover や onmouseout イベントを使って、マウスがページ中のある要素に重なる / 離れたときに変化を起こしている場合、onfocus や onblur イベントを使って、要素がフォーカスされた / 失った時も同じ変化を起こす
- フォームの独自実装
    - ラジオボタンやセレクトボックスなどを独自実装している場合、通常期待される挙動をキーボードでも実現できるような実装を自前で追加する必要がある

### 代替手段を提供する

- dblclick 及び mousemove のようなマウス固有の機能には、対応するキーボード固有の機能がない
- 実装されているマウス固有の機能と同等の機能を、キーボードから実行できるように機能を追加する必要がある
    - 例：マウス操作でファイルをアップロードする場合、ドラッグ＆ドロップだけでなくキーボードによってエクスプローラーからファイルを選択できるようにする
