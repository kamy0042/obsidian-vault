# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- マルチポイントまたは軌跡ベースのジェスチャを使って操作する機能には、<u>軌跡ベースのジェスチャなしのシングルポインタ</u>での代替操作を提供する
- 様々なポインティングデバイス、能力、および支援技術とともにコンテンツをコントロール可能にする
    - ジェスチャを正確に実行できない人、ヘッドポインタ、視線システム、音声制御マウスエミュレーターなどの特殊な、または適合した入力デバイスを使用しても、コンテンツのコントロールを確実に行えるようにする
        - ポインティングの方法の中には、マルチポイント又は軌跡ベースのジェスチャ実行の能力又は精度が不足しているものもある
- ポインタの動きは、正確な動きを実行できない人にとって、使用が困難又は不可能である可能性があるため、代替の形式のインタラクションが常に推奨される
- マルチポイント又は軌跡ベースのジェスチャなしにコンテンツを操作できることを保証しなければならない
    - タップ、クリック、ダブルタップ、ダブルクリック、長押し、クリック＆ホールドなどの別の方法でも機能を操作できる限りにおいて、マルチポイント又は軌跡ベースのジェスチャを使用することができる
- タッチスクリーンデバイスでの挙動が不明な場合、テストを行うことが重要
    - タッチスクリーンデバイスのブラウザは、一般的に軌跡ベースのジェスチャが必要かどうかに影響を及ぼすいくつかのデフォルトのジェスチャを提供する
        - タッチスクリーンデバイス上のウェブブラウザは、垂直方向のジェスチャを検出してページをスクロールすることがある
            - 利用者がスライダーのつまみに指を置いて上に動かすと（下にスクロールするため）、スライダーが作動しないことがある（実装による）
    - アクセシビリティ サポーテッドとしてタッチスクリーンデバイスを含める場合、同様の方法でマウスを使用しても同じブラウザの動作をトリガーしないため、このタイプのインタラクションはタッチスクリーンでテストする必要がある
- 一般にコンテンツ制作者は、複雑なジェスチャと同等の動作を実行するキーボードコマンド又は他の非ポインタメカニズムを提供する必要がある（[2.1.1 キーボード［A］](https://chatwork.atlassian.net/wiki/spaces/BRDG/pages/3742959092) ）が、この達成基準に適合するためには十分ではない
    - ポインティングデバイスに完全に依存している又は単純なポインタ入力が、代替手段よりもはるかに実行しやすく理解しやすいと感じる利用者がいる
        - ヘッドポインタに依存している利用者は、キーボードショートカットをエミュレートするためにスクリーンキーボードを動作させるよりも、コントロールをクリックする方がはるかに使いやすいと感じるだろう
        - 一連のキー（又はジェスチャ）を覚えるのが困難な人は、ラベル付きコントロールをクリックする方がはるかに簡単であると感じるだろう

**ポインタのジェスチャに関係する用語**

- マルチポイントジェスチャ
    - 単一の指または棒でタイプ／ポイント<u>しない</u>ジェスチャ
    - 例
        - 2本指のピンチズーム
        - 1本目の指を画面上に置いて2本目の指をタップするスプリットタップ
        - 2本指もしくは3本指のタップまたはスワイプ
- 軌跡ベースのジェスチャ
    - 始点から終点（の解除）だけではなく、中間点の通過にも意味を持つようなものは軌跡ベースのジェスチャ
        - 中間点は、完全な軌跡が定義されていない場合も含まれる
    - スワイプ、スライダー、カルーセル、形状の描画も軌跡ベースジェスチャ
        - 操作はトラックパッド、スタイラスペン、ジョイスティック、マウス、その他ポインタデバイスが使われる
    - ドラッグ操作においては、始点と終点のみが重要であるため、軌跡ベースジェスチャではない
        - が、ドラッグしない方法の提供も推奨されている

## **例外**

デザイナー エンジニア

- マルチポイント又は軌跡ベースのジェスチャが必要不可欠である場合
    - 署名の入力
- 自由形式の軌跡の代替を提供することが困難又は不可能な場合があるため、軌跡ベースのジェスチャに限定される
    - 自由形式 ＝ 終点の前に特定の経路を必要とせず、始点と (オプションで) 終点のみが重要
Open
- タッチスクリーンでのみ軌跡ベースのジェスチャが必要（マウスでは不要）なケースもある
    - マウス：左右スクロールは、スライダーを移動させる（スライダーにフォーカスしてドラッグする）ことで操作している限り、垂直方向のページのスクロールが発生しない＝マウスポインタを利用した、<u>軌跡ベースのジェスチャは不要</u>
    - タッチスクリーン：スライダーのツマミコントロールに指を置き、横よりも上に移動する場合、ブラウザがスワイプを制御してスクロールとして解釈し、ページを上下に移動させるため、スライダーが応答しないことがある
        - スライダーのつまみを左右に動かすとスライダーが動き、利用者は垂直方向の動きを変えることができる＝タッチスクリーンデバイス上の<u>軌跡ベースのジェスチャ</u>
- オペレーティングシステム、ユーザーエージェント、又は支援技術によって定義されたジェスチャには適用されない
    - オペレーティングシステムのジェスチャ例
        - システム通知を表示するための下方向へのスワイプ
        - 組み込みの支援技術のためのジェスチャ
    - ユーザーエージェントが実装するジェスチャの例
        - ページ履歴内を移動する、ブラウザが実装する水平方向のスワイプ
        - ページのコンテンツをスクロールするために用いられる垂直方向のスワイプ
- すべての機能がポインティングデバイスで利用できることを要求するものではない
    - が、ポインタデバイスで使用できる場合は、軌跡ベースのジェスチャを要求すべきでない
- （再掲）ドラッグ操作では始点と終点のみが重要であるため、任意の方向へのドラッグを伴うジェスチャは、この達成基準の範囲には含まれない

# **どう実装したらこの達成基準を守れるか？**

エンジニア

### 事例１：スワイプによって複数のコンテンツを切り替える場合

- 例：YouTubeのショート動画など
- 入力の代替手段として矢印ボタン等を提供すれば、シングルポインタによる操作でコンテンツを切り替えることができる
- この達成方法はコンテンツ制作者によって実装されているジェスチャを対象とするため、下記は対象外となる
    - ユーザエージェントが提供するジェスチャ
        - 水平スワイプによるブラウザ履歴間の移動
        - 垂直スワイプによるページコンテンツのスクロール など
    - OSが提供するジェスチャ
        - 開いているアプリ間の移動
        - 利用可能な支援技術のコンテキストメニューの呼び出し など
- タッチスクリーンデバイスでOS レベルの支援技術 (AT) がオンになっている場合、コンテンツ制作者が提供する軌跡ベースのジェスチャは機能しない
    - 例：OSが提供するスクリーンリーダー
- 軌跡ベースのジェスチャを支援技術が消費してしまい、制作されたコンテンツにまで届かないため
    - コンテンツスライダー上で水平方向にスワイプするジェスチャは、スクリーンリーダーのフォーカスを次または前の要素に移動させる
- 一部のジェスチャは、利用者が「パススルージェスチャ」の操作を行うことで機能する場合がある
    - とはいえハードウェア、オペレーティングシステム (OS) の種類、OS のスキン、OS の設定、ユーザエージェントといった要因に依存するため、信頼性が低いことが多い

### 事例２：コントロールスライダーの場合

Open

コントロールスライダー

- スワップまたはドラッグによって操作されるコントロールスライダーは、タップやクリックによって値を設定できるように実装する
- スライダー上のクリックだけでなくボタンなどを提供することで、より細かな操作も可能になる
    - `<input type='range'>`の場合、クリックによる操作は可能だがボタンは存在していない
    - [https://www.w3.org/WAI/WCAG21/working-examples/providing-single-point-control-slider/](https://www.w3.org/WAI/WCAG21/working-examples/providing-single-point-control-slider/) のように、コントロールスライダーとボタンを組み合わせることでより操作しやすくなる

### 事例３：Google map の場合

- キーボード操作による代替手段が提供されている
    - [https://support.google.com/maps/answer/6396990?hl=ja&co=GENIE.Platform%3DDesktop](https://support.google.com/maps/answer/6396990?hl=ja&co=GENIE.Platform%3DDesktop)
    - 地図を動かす: Shift キーを押しながら矢印キー
    - ズームイン／アウト：プラスまたはマイナスキー
- シングルポインタによる代替ではないものの、操作手段を提供するという観点では問題ない？
