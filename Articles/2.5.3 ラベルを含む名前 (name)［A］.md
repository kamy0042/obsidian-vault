# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- コンポーネントに視覚的にラベルを付ける単語が、コンポーネントにプログラムにより関連付けられる単語でもあることを確実にする
    - 障害のある人がコンポーネントとやりとりする手段として可視ラベルを確実に信頼できるようにするのを助ける
    - ほとんどのコントロールに付けられている可視のテキスト**ラベル**と、プログラム上にあるアクセシブルな**名前**（Accessible Name）の単語及び文字が一致する、あるいはアクセシブルな名前に含まれていると、
        - 音声入力の利用者が画面に表示された、メニュー、リンク、ボタンなどの可視ラベルを話すことで操作可能になる
        - 読み上げ利用者が、聞こえるテキストが画面に表示されるテキストと一致してよりよい体験が得られる
- テキストラベルが存在し、（確立されたオーサリングプラクティスを通じて）UIコンポーネントに適切にリンクさせていればラベルと名前は一致する
    - アクセシブルな名前と可視ラベルが異なる場合、音声入力時などに誤って作動する懸念のある非表示のコマンドになってしまう
    - 可視ラベルとプログラム名の不一致は、認知の問題を抱える音声入力／読み上げ利用者にとって問題になる
        - 覚えなくてはいけない
        - 認知負荷が掛かる
- 画面上のどのテキストをコントロールラベルとみなすかを決める必要がある
    - ラベルは、<u>近接したテキスト</u>のみとするのが最良
        - コンボボックス、ドロップダウンリスト、テキスト入力、及びその他のウィジェットのすぐ左
            - 又は、左側のラベルがない場合、各入力のすぐ上で左端に揃えられる
        - チェックボックス及びラジオボタンのすぐ右側
        - ボタン及びタブの内側、又はボタンとして機能するアイコンのすぐ下
    - 上記の根本原理は一般事項として（WCAGの達成方法集[G162: 関係性を最大限に予測できるようにするためにラベルを配置する](https://waic.jp/translations/WCAG21/Techniques/general/G162)で）定義されている
![](https://waic.jp/favicon.ico)
- テキストラベルを構成するものを自由に解釈すると、予測可能性の低下によりこの達成基準の価値が危険にさらされる可能性があるため、隣接するテキストのみをラベルとして扱うようにバイアスをかけることが重要
    - コンポーネントに近接した単一の文字列にラベルを分離すると、開発者、テスター、およびエンドユーザがこの達成基準で評価の対象となるラベルを簡単に特定できるようになる
        - 音声認識技術の利用者は、伝統的な位置にあるラベルを通して要素とやりとりできる
        - 画面読み上げ技術の利用者は、近くに表示されるラベルとコンポーネントの通知された名前との間の一貫性を得ることを可能にする
- 入力フィールド内のプレースホルダーテキストは、ラベルを提供する適切な手段とは見なされない
    - [HTML5仕様](https://html.spec.whatwg.org/multipage/input.html#the-placeholder-attribute) では、プレースホルダー属性を`<label>`の代わりに使用すべきでないと記述されている
        - しかし、近くに他のテキスト文字列がない場合に、入力にプレースホルダーテキストが含まれていれば、（視覚的に一番近くにあるため）それがラベルを含む名前（name）として機能する
            - ってことも考慮しろよっていう話しなだけである、と解釈してよさそう
            - ただし前提としては、アクセシブルな名前（accessible name）と可視ラベルが他に提供されない場合
        - アクセシブルな名前（accessible name）の計算についての補足
            - 特定の属性や優先順位により、最優先のものだけが計算される
            - 好ましくない値は名前（name）の一部にならない
                - ほとんどの場合、ラベルとコントロールの間に確立されたプログラム上の関係が仕様により最優先
            - ネイティブセマンティクスの名前（name／accessible name）はAIRAで上書きされる
                - ARIAは慎重に使用・設定すべき
            - 計算に含まれ**ない**：見出し、指示、グループラベル（`legend/fieldset`, `group`, `radiogroup` のrole）など
                - 達成基準上の「ラベル」**にはならない**
                - ならないが、`aria-describedby`で関連付けられたテキストがスクリーンリーダーによってアクセシブルな名前の直後に通知されるため、見出し、指示、グループラベルのコンテキストはスクリーンリーダーの利用者を支援する

Accessible Name（and Description Computation）だけで仕様書が存在するくらい難解なやーつ：[https://www.w3.org/TR/accname-1.1/](https://www.w3.org/TR/accname-1.1/)

# **どう実装したらこの達成基準を守れるか？**

エンジニア

### 可視ラベルをアクセシブルな名前として設定する

これまで出てきたように、セマンティックなマークアップを行なっていれば自然と達成できることが大半

- [https://chatwork.atlassian.net/l/cp/gP1NPK0K](https://chatwork.atlassian.net/l/cp/gP1NPK0K)
- [https://chatwork.atlassian.net/l/cp/qV9AEK8P](https://chatwork.atlassian.net/l/cp/qV9AEK8P)

### 注意が必要なシチュエーション

いくつか誤解を生みそうなUIがあるので下に記載する

### ラジオボタンのグループ

Open

- この場合、ラベルはそれぞれ「Yes / No」にするべき
    - ラジオボタンに隣接している文字列がラベルとなる
- 下記のように「何がラベルを構成するか」という点で複数の解釈を許すと、スクリーンリーダーの利用者に悪影響を与えることがある
    - "Call me when balance exceeds $10,000"がラベルになる？
    - もしくは”Call me when balance exceeds $10,000 Yes" ?
    - または"Yes, Call me when balance exceeds $10,000”?
        - その場合、Noだと"No, call me when balance exceeds $10,000" という読み上げになるので非常に使いにくい

```plain text
// 推奨されるマークアップ例
<fieldset>
  <legend>Call me when balance exceeds $10,000?</legend><br />
  <input type="radio" id="yes" name="callme" value="yes">
  <label for="yes">Yes</label>
  <input type="radio" id="no" name="callme" value="no">
  <label for="no">No</label>
</fieldset>
```

### チェックボックスのグループ

Open

- この場合も、コンポーネントのラベルは "Courtesy"、"Promptness"、"Store Hours" 及び "Knowledge" に限られるべき
- 説明用のテキストをラベルに含めると、何度も同じテキストが読み上げられるので好ましくない
- 音声入力によるコントロールも難しくなる

### 積み重ねられたラベル

Open

- ラベルとフォームが隣接していれば問題ないが、このように説明文が挟まる可能性もある
- この例だとコントラスト比やタイポグラフィーによって視覚的に関連づけられていると言えるが、さらにマークアップによって関連付け情報を与えることが望ましい
    - ラベルとフォームの関連付け ※`for属性`
    - フォームと説明文の関連付け ※`aria-describedby`
- 説明文がより長くなると視覚的な関連性が薄れる可能性があるため、1行に収めた方が良い

```plain text
// 推奨されるマークアップ例
<form>
  <label class="label" for="example-2">
  Password
  </label>
  <span id="example-2-hint" class="hint">
  Passwords must be 10 or more characters, and contain at least one capital, numeric and non-alphanumeric.
  </span>
  <input class="input" id="example-2" name="example-2" type="text" aria-describedby="example-2-hint">
</form>
```

### 範囲入力及びわずかなラベル

Open

- ラベルが範囲の両端に配置される or 範囲のさまざまな場所に散っている可能性もある
- この例だと、"Hated it" 及び "Loved it" の二つのラベルはそれぞれ両端のラジオボタンのアクセシブルな名前となる
- 中央の３つは可視ラベルを持たないため、それぞれ`title`属性を与える
    - 不可視テキストとして`label`をマークアップしても良いのかも？
    - `title`属性だとマウスオーバーでツールチップが表示されるメリットもあるが、その挙動は利用状況に左右される
        - 常にツールチップを表示させるならば自前で実装する必要がある

```plain text
// 推奨されるマークアップ例
<fieldset>
  <legend>Rate your response</legend>
  <label for="hated">Hated it</label>
  <input type="radio" name="meal" id="hated" value="hated">
  <input type="radio" name="meal" id="poor" value="poor" title="Disliked">
  <input type="radio" name="meal" id="neutral" value="neutral" title="So-so">
  <input type="radio" name="meal" id="okay" value="okay" title="Liked">
  <input type="radio" name="meal" id="loved" value="loved">
  <label for="loved">Loved it</label>
</fieldset>
```

### アクセシブルな名前の一部として可視ラベルのテキストを含める

- 可視ラベルを構成するテキスト文字列全体がアクセシブルな名前内に存在しなければならない
- 追加のコンテキストが必要とされるほとんどの状況では、可視テキストを追加テキストの前に置くことが推奨される
- それにより、音声入力を行う利用者は入力が正しく解釈されると確信できる

```plain text
// 例：スクリーンリーダー用の不可視テキストを可視テキストの後に追加する
<p>
  Go to
  <a href="code-of-conduct.html">
    Code of conduct
    <span class="hidden_accessibly"> of ACME Corporation</span>
  </a>
<p>
```

- ボタンの場合も同様

```plain text
// ボタンの可視テキストとアクセシブルな名前の先頭を一致させる
<button>Send <span class="accessibly-hidden"> Mail</span></button>
```

### 見出しと紐づくリンクテキスト

- 段落の見出しと組み合わせてコンテキストを提供する
- この場合はページ上にある可視テキストを使用するため、（ブラウザ等の機能によって）適切に翻訳される可能性が高くなる

```plain text
// aria-labelledbyによって、リンクのアクセシブルな名前は
// 'More... Insufficient Link Names Invade Community'となる
<h4 id="poor">Insufficient Link Names Invade Community</h4>
<p>
  Citizens are reeling from the growing invasion of useless "read more" links appearing in their online resources.
  <a href="poor.html" aria-labelledby="generic poor">
    <span id="generic">More...</span>
  </a>
```

### aria-label に含まれるリンクテキスト

`aria-labelledby` を使用して2つの文字列を文法的又はシームレスに組み合わせることができない場合、`aria-label` を使用して、可視ラベルを含む新しい名前 (name) を作成することができる

```plain text
...end of news story.
<a href="poor.html" aria-label="Read more about Insufficient link names">
  Read more
</a>
```
