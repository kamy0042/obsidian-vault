# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- ユーザーから情報を収集するフォームの入力の目的をプログラム的にも解釈可能にし、ユーザーエージェントが異なってもユーザーにその目的を提示できるようにする
    - 適切なラベルと説明はユーザーが入力フォームの目的を理解するのに役立つ
- 特定のフィールドで期待される特定の種類のデータをプログラムで宣言する
    - 特定の情報を収集するフィールドは、ユーザーエージェントのデフォルト設定や支援技術を使って、曖昧さなく一貫して表示されるため、ユーザーにとって使いやすくなる
        - 特に認知障害を持つ人々にとって、フォームへの入力が容易になる
- ユーザインタフェースコンポーネントの入力目的の種類を定義し、プログラムによって特定可能でなければならない
    - 利用者の入力目的が存在しそれを技術がサポートしている場合、フィールドの目的はプログラムによって特定可能でなければならない
- type属性が既に入力フィールドの意図を広く指定する方法を提供しているが、必ずしもその目的は説明されていない
    - 例えば、`type="email"` はそのフィールドがEメールアドレス用のフィールドであることを示すが、その目的が利用者のEメールアドレスを入力するためのものなのか、他の人のEメールを入力するためのものかは明確にしない
    - HTMLのautocomplete属性は、一定数の特定の明確に定義された固定値のみを受け入れる。これにより、例えばコンテンツ制作者が特定のタイプの名前（名前`autocomplete="name"`、Given Name`autocomplete="given-name"`、Family Name`autocomplete="family-name"`、に加えてユーザ名`autocomplete="username"`及びニックネーム`autocomplete="nickname"`）を指定できるようにすることで、type属性よりもよりきめ細かい定義又は目的の特定が可能になる定できるようにすることで、type属性よりもよりきめ細かい定義又は目的の特定が可能になる
        - <u>所定の定義の分類法</u>を採用して再利用することで、ユーザエージェントと支援技術は、異なるモダリティで利用者に入力の目的を提示できる
            - 読むのが困難な利用者を助けるために、支援技術は入力フィールドの隣に見慣れたアイコンを表示してもよい
                - 誕生日ケーキのアイコンを`autocomplete="bday"`の入力フィールドの前に表示してもよい
                - 電話のアイコンを`autocomplete="tel"`の入力フィールドの前に表示してもよい
                - 脳性麻痺、脳卒中、頭部損傷、運動ニューロン疾患又は学習障害を持つ人々は、コミュニケーションのために画像を好むことがある
                    - 彼らは、フィールドの目的を視覚的に伝えるために、入力フィールドにアイコンを追加する支援技術を使用できる
        - autocomplete属性を使用してこの達成基準を満たす場合、ブラウザ及び他のユーザエージェントは、ブラウザに保存された過去の利用者の入力に基づいてこれらのフィールドを自動補完して正しいコンテンツを提案及び「自動入力」できる
            - 一般的な入力目的のより詳細な定義、例えば「Birthday」`autocomplete="bday"`を定義することによって、ブラウザはこれらの各フィールド（利用者の誕生日）にパーソナライズされた値を保存できる
                - 利用者は情報を入力する必要がなくなり、代わりに入力値を確認又は必要に応じてフィールドの値を変更できる
                - 記憶の問題、失読症、その他の障害を持つ利用者にとって著しい恩恵である
                - ブラウザが個人情報 (名前や住所などの) を自動入力することで恩恵を受ける
                    - つまり、利用者がそれらの情報を記憶する必要がない
                - 運動障害を持つ人々はまた、フォームを埋めるときに手入力の必要性を減らすことで恩恵を受ける
            - autocompleteの値は言語に依存しないため、ユーザ入力フィールドを視覚的に特定するために利用されるテキスト（ラベル）に馴染みのない利用者は、用語の固定された分類法によって、その目的を一貫して特定できる
- 1つの入力フィールドが2つの異なる種類の入力目的を受け入れ、かつ使用されている技術で複数の目的の値を定義できない場合、どちらか一方の値を提供する、又は入力目的の指定を完全に省略するのが妥当
    - ユーザ名／利用者の電子メールフィールドを兼ね合わせるようなやつ

# **どう実装したらこの達成基準を守れるか？**

エンジニア

- autocomplete属性を利用する
- 下記の属性で利用可能
    - input
    - textarea
    - select
    - form
        - `on`と`off`のみ設定可能
        - ここで設定した値よりも個別の要素に設定した値が優先される
- `label`要素,`id`,`name`に設定された値や他の項目を参照してブラウザ側で判断することも可能
    - autocomplete属性を指定したときはそちらが優先される

### autocomplete属性のonとoff

- `on`:
    - 自動的に項目を補完する
- `off`:
    - ユーザーが入力したデータを保存しない（部分的に嘘）
        - 動作はブラウザによって異なる
    - 項目を補完しない（部分的に嘘）
        - 現代的なブラウザはログインフォームにおける`autocomplete="off"`を無視する
            - 「強固なパスワードをブラウザに覚えさせて利用する方がセキュリティ向上するよね」という思想
            - パスワード欄の自動入力を抑止したい場合は、 `autocomplete="new-password"` を使用する
        - Chrome等のブラウザだと、そもそも`autocomplete="off"`だけだと無効化されない
            - `label`要素,`id`,`name`に設定された値を参照してブラウザ側で判断している
    - 基本的には`on`にするべきという意志を感じる…

### 利用可能なautocomplete属性

[https://developer.mozilla.org/ja/docs/Web/HTML/Attributes/autocomplete](https://developer.mozilla.org/ja/docs/Web/HTML/Attributes/autocomplete)

### 住所指定時の行政区分

- 住所指定時は、`address-level1` ～ `address-level4`の順でより詳細な行政レベルとなる
- 地域によって使用するレベルや並び順が異なる
    - アメリカ：2つのレベル（州および町）
        - 町（レベル2）は、州（レベル1）に先行して使用する
    - イギリス：1~2つのレベル（郵便町、場合によっては地域）
    - 中国：3つのレベル（県、市、区）
- 日本の場合
    - [https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#more-on-address-levels](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#more-on-address-levels) だと`address-level3`までしか言及されていない
    - [https://www.japan-guide.com/e/e2224.html](https://www.japan-guide.com/e/e2224.html) を見る限り、`address-level4`までフルに使って良いのでは…？
    - [https://developer.mozilla.org/ja/docs/Web/HTML/Attributes/autocomplete#%E6%97%A5%E6%9C%AC](https://developer.mozilla.org/ja/docs/Web/HTML/Attributes/autocomplete#%E6%97%A5%E6%9C%AC) だと2～3の行政レベルを使うと記載
    - 仕様書である[https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#more-on-address-levels](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#more-on-address-levels) に沿うと、
        - `address-level1`：都道府県
        - `address-level2`：市区町村
        - `address-level3`：地区
