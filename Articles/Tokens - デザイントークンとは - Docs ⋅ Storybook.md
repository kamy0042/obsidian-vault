# **デザイントークンとは**

デザイン上の意思決定を名前と値のペアとして表した、UIを構成する最小要素です。

※ 例：`color-text-primary: #000000;`

デザイントークンの種類としてカラー、タイポグラフィ、スペーシングなどが存在します。

また、トークンとはデザイナーの設計意図を構造化したものであり、デザインとエンジニアリング間の共通言語としても機能します。

# デザイントークンのメリット

**以下の働きによってプロダクト開発をサポートします**

- **デザイナーの設計意図の見える化**
    - 判断に迷う場面を減らし、より本質的な課題に集中できます
- **プロダクトに関わる人たちへの共通言語の提供**
    - 職種間でUI設計についてコミュニケーションを取りやすくなります
- **一貫性のあるUIの提供**
    - ユーザーの認知的負荷や学習コストの削減に繋がります

# デザイントークンは〇〇ではありません

- 遵守するべきルールではありません
    - あくまでもプロダクトに関わる人をサポートするノートであり、規則ではありません
- 不変の定義ではありません
    - 現状のUIから抽出し構造化したものであり、今後改修が加わる可能性もあります
    - ここに記載した内容が決定稿ではなく、フィードバックに基づいて改修を行なっていきます
- 特定の職種のみ利用するものではありません
    - 認識の齟齬を減らすため、プロダクトに関わる全ての人の共通言語となることを意図しています

# デザイントークンの種類

ChatworkではGlobalトークンとAliasトークンの2種類を定義しています。

各トークン（＋元々の値）は下記の図のような階層構造を持ちます。

### **Globalトークン**

UIの一番の基礎となる構成要素であり、特定の文脈を持ちません。

例えば色の場合、これまで利用していたカラーパレットがGlobalトークンに該当します。

例：`colors.Casper.55: hsla(212, 33%, 51%, 0.50);`

基本的には直接Globalトークンを用いるのではなく、後述のAliasトークンから参照する形で利用します。

歴史的経緯などにより適切なAliasトークンが存在しない場合のみ、Globalトークンの直接利用を許容します。

※ PrimitiveトークンやReferenceトークンと呼ばれることもあります

### **Aliasトークン**

何らかの文脈に沿って分類された、Globalトークンを参照するトークンです。

文脈ごとに意味のある名前が与えられることで、トークンがいつどのように使用されるべきか理解しやすくなっています。

例：`colors.background.status.positive: {global.colors.ForestGreen.light}`

「意味を持たせたトークン」という性質上、デザイナーの設計意図がより色濃く反映されたものでもあります。

※ SemanticトークンやSystemトークンと呼ばれることもあります。

「意味性 = セマンティクス」を持たせたトークンではありますが、単語のわかりやすさを優先し、Aliasトークンという名称を採用しました。
