# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- ウェブページ上で、3秒より長く音声が自動に再生される場合、以下を用意する
    - 一時停止または停止できる
    - システム全体の音量レベルに影響を与えずに音量調整できる
        - 音量調整の最低音は、無音
- スクリーンリーダーに干渉させずに、背景音のコントロールができる
    - スクリーンリーダーで操作をする人には、背景音が邪魔になり操作できなくなってしまう
- 音声ファイルの自動再生が行われても、すぐに先頭の「音を消す」アクションを使える
- WCAGワーキンググループでは、自動的に再生される場合、スクリーンリーダーユーザーは操作側の読み上げが聞き取れず「止める」ことに難が出てしまうため、**ユーザー側のアクションで再生されることを推奨**している
- 視覚的なコンテンツ閲覧中に、音声（の自動再生）で集中力が削がれない
- この基準が**クリアできないと干渉につながる**ため、超重要

    - アクセスすることを妨げないことを「非干渉」と表現される

            - その他の例2：すごく動くコンテンツ（バナーなど）があるせいで、メインコンテンツに集中できない ← 干渉している

# **どう実装したらこの達成基準を守れるか？**

エンジニア

- 大まかな方針としては下記の３つ
    - 自動再生される音声を3秒以内に収める
        - 3秒を超えなければ達成基準はクリアできる
    - ページの先頭付近に、自動再生される音声の停止ボタンを配置する
        - スクリーンリーダーで認識可能＆キーボード操作可能にしておく必要がある
    - そもそも自動再生しない
        - 再生タイミングを利用者自身に任せる
- 実装云々というよりも、設計段階で配慮しておく必要がある印象
    - 本当に自動再生する必要があるのかどうか
    - 3秒以内に収めることができないか 等

## **具体的なマークアップ方法例**

エンジニア

- [https://waic.jp/translations/WCAG21/Techniques/general/G60](https://waic.jp/translations/WCAG21/Techniques/general/G60)
    - そもそも、自動再生される音声を3秒以下に収めておけば問題ない
    - 実装方法というよりも、コンテンツを準備する段階で注意を払う
- [https://waic.jp/translations/WCAG21/Techniques/general/G170](https://waic.jp/translations/WCAG21/Techniques/general/G170)
    - スクリーンリーダーで認識可能＆キーボード操作可能なボタンを配置する
        - この辺は以前やったところなので割愛
    - ビジュアル面の都合で、先頭付近に配置できない時は Visually hidden パターンを用いる
        - 要するにボタンをスクリーンリーダーにのみ認識させる
        - とはいえ、スクリーンリーダーを利用しないユーザーに対しても停止ボタンを提供しなければならない
            - > この達成基準はまた、音声が再生されているとき、(テキストを含む) 視覚的なコンテンツに集中することが困難な人に対しても役に立つ
            - つまり、不可視のボタンと可視化されたボタンが存在することになる
            - 不可視のボタンもフォーカスできるので、キーボード操作を行う人（not スクリーンリーダー利用者）を混乱させないためにも、フォーカス時は表示させる方が良さそう
                - `:focus` ＝ フォーカス時の制御
                - `:focus-within`＝ その要素または子孫要素にフォーカスがある場合の制御
            - `// Bootstrap v5から引用
.visually-hidden-focusable:not(:focus):not(:focus-within) { position: absolute !important; // VoiceOverが読み上げるにはwidth, heightが1px以上必要 width: 1px !important; height: 1px !important; padding: 0 !important; margin: -1px !important; overflow: hidden !important; // clipは、要素の一部を切り抜き表示する際に用いる // この場合座標に0が指定されているのでどこも切り抜かれない = 非表示 clip: rect(0, 0, 0, 0) !important; // スクリーンリーダーに文中のスペースが認識されないバグへの対応 // https://medium.com/@jessebeach/beware-smushed-off-screen-accessible-text-5952a4c2cbfe white-space: nowrap !important; border: 0 !important;
}`
            - その他実装方法 [https://zenn.dev/yamanoku/scraps/a6c328ccc3238c](https://zenn.dev/yamanoku/scraps/a6c328ccc3238c)
        - 重複を避けるため、視覚的に表示させるボタンには `aria-hidden:true`を指定するべき？
            - 指定すると、そのボタンにフォーカスした際に何も読み上げられなくなる
            - それによる混乱を避けるため、重複を許容した方が無難か
- [https://waic.jp/translations/WCAG21/Techniques/general/G171](https://waic.jp/translations/WCAG21/Techniques/general/G171)
    - 再生ボタンや音声ファイルへのリンクを提供する
