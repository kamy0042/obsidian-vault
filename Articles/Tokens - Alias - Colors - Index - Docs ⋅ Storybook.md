# **色のAliasトークン：概要**

色のAliasトークンとは、カラーパレットに存在する色に意味を持たせて構造化したものです。

基本的にはここで定義したトークンを用いてUIを設計します。

既存のUIから色の使われ方を抽出し、コンテキストに合わせて分類したものであり、デザイン上の意思決定とそのロジックの言語化を意図しています。

このように色の利用方針の言語化を行うことで、UI設計の効率化や堅牢さの獲得、メンバー間の共通認識の形成を期待できます。

色のAliasトークンは個別のUIごとに定義されたものではなく、色の使われ方を抽象化して分類したものです。

1つのUIの配色を設計するために複数種類のAliasトークンを利用することもありますのでご注意ください。

# Aliasトークン：色の設計方針

トークンは下記の図の構造を取ります。

```plain text
プロパティ（background, text, border）
    └ コンセプト（status, action等）
        └ 状態（default, hovered, pressed, disabled）
            ┝ type（トークンの種類 ※トークンの仕様上必要となる項目です）
            └ value（色の値 ※Globalトークンへの参照）

例：ユーザーが操作するUIの背景色：background.action.primary.default.value

Copy

```

プロパティ、コンセプト、状態の説明は下記の通りです。

### **プロパティ**

UI内の部位ごとの分類です。

background, text, borderの3種が存在しており、利用箇所に基づいてトークンをグループ化しています。

### **コンセプト**

色の利用意図ごとの分類です。

意図に基づいて分類し、意味のある名前を持たせることで、利用シーンに応じた最適なトークンを参照しやすくします。

同じコンセプトでも適用するプロパティ（background,text,border）によって色が異なる場合や、特定のプロパティのみ存在している場合もあります。

意味を持たせつつ柔軟性を維持するため、コンセプト内で複数の階層を持つことも許容します。

### **状態**

UIの状態ごとの分類です。

default, hovered, pressed, disabledの4種が存在し、UIの状態に応じた色やトーンの変化を表します。

上記の変化が存在しない場合はこの項目を含めません。

※この項目を利用する場合、未操作時の値（default）と各状態を兄弟要素として扱う必要があります。

※フォーカス時の色はコンセプトごとに分ける必要性が薄いため、状態ではなくコンセプトの１つとして扱います。
