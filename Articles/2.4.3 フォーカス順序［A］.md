# **この達成基準は、どうなっていたらクリアと言えるのか？**

デザイナー

- コンテンツ内を一つずつ順を追いながら行き来している際に、キーボードにより操作可能な順序でコンテンツの意味に添って、情報と出会うようにする
    - 利用者のコンテンツに対するメンタルモデルを一貫したものとし、利用者が困惑する懸念を引き下げる
        - 字を読むのが困難な障害のある利用者が、Tabキーでの操作でフォーカスを見失わない
        - 画面拡大ソフトを使用して拡大率を高くしている利用者には、フォーカス順序が論理的でないと、誤った文脈でコンテンツの一部分を解釈させる恐れがある
- ナビゲーションの “一般的な” 順序は、技術により定義される
    - HTML：タブ移動順序によってナビゲーション順序を定義する
- キーボードナビゲーション（ツリーコンポーネントを行き来するための矢印キーを用いたナビゲーション）などもある
    - `▶`でノードを展開して`▼` `▲` で新しく展開されたノードへ移動する
    - アイテムの開閉が行われるたびに、ナビゲーション順序に追加されたり削除されたりするため、このナビゲーション順序はツリーコントロールで予期される順序に従う
- フォーカス順序と音声読み上げ順序が一致しない場合もある
    - コンテンツに対して考えられうる論理的な音声読み上げ順序が数通りあり、フォーカス順序はそのうちのどれかと一致するだけのケース（視覚的順序とスクリーンリーダーの読み上げ順序が一致しないなどのケース）
        - この場合、あらゆる利用者のことを想定したコンテンツ制作を行う必要がある

# **どう実装したらこの達成基準を守れるか？**

エンジニア

### インタラクティブな要素に対して、マークアップ内の順序とデザイン上の視覚的な順序を一致させる

- HTMLの場合、デフォルトのフォーカス順序はマークアップ内で要素が出現する順序に従う
    - キーボード利用者は、マークアップの順序と視覚的な順序が一致しない場合に、次にフォーカスが移動する場所を予想するのが困難
    - CSSやJSによって視覚的な順序を入れ替えることが可能だが、それは避けるべき
    - JSやtabindex属性によってフォーカス順序を操作することも避けるべき
        - ただし、モーダルを開いたときなど、表示される情報構造が変化したときは別
            - モーダル内のフォーカス可能な要素でループさせる必要がある
- 動的に要素を生成した時も、トリガーとなった要素の直後にDOMを挿入することが望ましい
- インタラクティブでない要素に対しても、マークアップの順序と視覚的順序と一致させることが望ましい
    - スクリーンリーダーでページコンテンツを読んでいる全盲の利用者が、視覚的な順序で読んでいる目の見える利用者と一緒に作業している場合、異なる順序で情報を得るので混乱するかもしれない
    - マークアップの順序が視覚的順序と一致する場合、全ての人が同じ (正しい) 順序でコンテンツを読んで情報をやり取りできる
- アプリケーションにおける視覚的な順序ってどう判断するべき？
    - コンテンツ間の関係性を定める必要がありそう
    - 情報設計が大事

### HTMLのtabindex属性について

- `tabindex="0"`
    - tabindex が**正の値の要素の後に**フォーカス可能
    - 複数存在する場合の順序はマークアップ順に依存
- `tabindex="正の値"`
    - 数字が小さいほど先にフォーカスが当たる
    - 同じ数字が複数存在する場合はマークアップ順に依存
    - 最大値は`32767`
- `tabindex="負の値"`
    - クリックだとフォーカスできるがTabキーだとフォーカスされない
    - つまり、キーボード操作だとクリックできなくなる

> 警告: tabindex の値として、0 と -1 のみを使用することをお勧めします。tabindex の値を 0 より大きくしたり、フォーカス可能な HTML 要素の順序を変更できる CSS プロパティ（フレックスアイテムの順序）を使用したりしないようにしましょう。これは、キーボードによるナビゲーションや支援技術を使用している人にとって、ページのコンテンツを操作することが難しくなります。代わりに、論理的な順序で要素を記述してください。

[https://developer.mozilla.org/ja/docs/Web/HTML/Global_attributes/tabindex](https://developer.mozilla.org/ja/docs/Web/HTML/Global_attributes/tabindex)

- もし正の値を付与して順序を管理しようとした場合、そのページ内の全てのフォーカス可能な要素を考慮しないと意図しない操作を引き起こす可能性がある
- 「正しいフォーカス順」を保守するのが非常に難しい
