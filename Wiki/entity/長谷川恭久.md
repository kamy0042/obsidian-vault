# 長谷川恭久

## 概要

Web・アプリのデザイナー。組織でより良いデザインができるようプロセスや仕組みの改善に注力し、ブログ（yasuhisa.com / could）・ポッドキャスト配信・講師業を行う（出典: [[デザインシステムは最優先にはならないです]] 著者プロフィール）。デザインシステム言説では「効率化・時間解放」ナラティブへの冷静な反論と、定義に固執しない組織起点のアプローチで一貫する。

## 主要な事実

- **時間解放の神話**: 「実装負担が減り創造的な仕事に時間を使える」は最も一般的な誤解で、時間は解放されず投資先が変わるだけ。効率向上がかえって総作業量を増やす「ジェボンズのパラドックス」に似た現象を指摘（出典: [[デザインシステムが変えるのは時間の使い方]]。詳細は [[デザインシステム批判論]] 軸11）
- デザインの意図を対話で明文化し「資産化」することが DS の真の価値という立場（出典: 同上。詳細は [[デザインシステムのドキュメンテーション]]）
- **「全員が優先して使うだろう」という誤った想定**と定義への固執が負のサイクルを加速させる。DS 構築支援の依頼に対し、UIライブラリではなくレビュープロセスと「なぜその見た目にしたのか」のドキュメンテーション整備から始めた事例を持つ——「デザインシステムを作る前にデザインのシステムを理解する」（出典: [[デザインシステムは最優先にはならないです]]。詳細は [[デザインシステムの投資対効果]]）
- **「デザインのシステム」論**（思想の中核）: デザインシステムを「コンポーネントライブラリと詳細度の高いガイドライン」ではなく「**組織におけるデザインのシステム（＝プロダクトを作り上げるあらゆる要素と関係）を改善する取り組み**」と再定義する。Lightning や Carbon のような完成形と言葉を結びつけるのは危険で、事例のようなものは「5年後の遠い目標」に置き、コンポーネントを揃える前に「一貫性がない状態が生まれた要因」を組織のシステムの中から見つけることが先決（出典: [[デザインシステムを作る前にデザインのシステムを理解しよう]]）
- **UI コンポーネントは表層的な解決手段**: コンポーネントは「事業目標→プロダクトの価値→指標→意思決定」の積み上げの上に成り立ち、価値が明文化されていない組織では「一貫性がある」以外の判断材料を持てない。「一貫性のある UI ライブラリーより、メンバーの『良いプロダクト』への視点に一貫性があったほうが大きな力になる」——DS を「プロダクトをデザインするための仕組み作り」と捉える（出典: [[UIコンポーネント以外から始めるデザインシステム]]。詳細は [[デザインシステムの立ち上げ]]）
- **デザイン原則の「決める力」**: 原則のポエム化を避け、「△△も大事だけど、私たちは〇〇をあえて優先する」と言える優先順位の共有を求める（出典: [[デザイン原則を作るときに忘れてはならない「決める力」]]。詳細は [[デザイン原則]]）
- **前提合わせとサポートの線引き**: 「少人数だと自然に合っていた前提は、人が増えることで次第に合わなくなっていく」——DS の「効率化」は利用者の知識・スキルという前提に基づき、前提を合わせる活動（チャット・フォーム・オフィスアワー・勉強会の複数窓口）と「要件定義には関与しない」等の範囲の線引きがないと、的外れなクレームによる信用喪失か際限ない業務拡大に至る。「持続がすべて」（出典: [[デザインシステム浸透に欠かせないサポートについて]]。詳細は [[デザインシステムの浸透]], [[デザインシステムのガバナンス]]）
- 『育て方』刊行後の Q&A から: 大手が DS を公開できる最大の要因は関わる人数（Carbon はリポジトリに482人がコントリビュート）と長期維持人材／パイロットからの抽象化には意図・文脈の記録と DS チームの間接的関与が必須／DS の「破壊・改変」は表層的理由（整理がつかない・古い・担当者不在）では誰も賛同しない——**症状と向き合い、組織のインセンティブや開発プロセスという要因に正直に答える**（出典: [[デザインシステムに関する質問に答えました]]。詳細は [[デザインシステムの世代交代]]）
- ポッドキャスト Automagic を配信。#361 では佐藤伸哉と「定義や意義は組織や状況によって大きく異なる」「2つ以上のデジタルプロダクトを持つ組織という前提」等を議論（出典: [[361 デザインシステムを育てるのは難しいけど（佐藤伸哉さん）]]）
- [[Dan Mall]]『Design That Scales』邦訳『**デザインシステムの育て方**』（🌴本）の監訳者。「That Scales を『育て方』と訳す」センスは [[Nobuya Sato]] も称賛（出典: [[翻訳記事：デザインシステムチームの投資収益率（ROI）｜Nobuya Sato]]）。wiki 内では [[連合型デザインシステム]] の訳語の典拠
