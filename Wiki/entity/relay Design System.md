# relay Design System

## 概要

オープンネーム事業承継サービス relay の公開デザインシステム。
AIネイティブな開発基盤として、コードを正本にしたトークン・コンポーネント、DESIGN.md、アクセシビリティの責任分界、MCP、hooks、evalsを一つの改善ループに組み込んでいる（出典: [[AIネイティブを目指した「これまで」と「これから」｜agu  relay（リレイ）]]）。

## 主要な事実

- 2026年5月から8月中旬までの約3か月で構築し、記事執筆時点で240 PR、v0.25.1。既存6年のサイトへ段階導入するため、Tailwind CSS v4ベースのフレームワーク非依存CSSとCSS変数をnpm配布する（出典: [[AIネイティブを目指した「これまで」と「これから」｜agu  relay（リレイ）]]）
- トークン定義をTailwindの`@theme`からCSS変数として直接配布し、「定義はあるが実装値が違う」状態を避ける。リポジトリを正本とし、Figmaは完成仕様の保管場所から探索と最終調整の場へ役割を変えた（出典: 同上）
- 狩野モデルを品質責任の分割に用いる。DESIGN.mdの「譲れない原則」（ハードコード禁止、余白の段階、本文サイズ等）を当たり前品質、「迷ったときの判断基準」を一元的品質とし、指摘が増えた基準は前者へ移して仕組みに引き渡す（出典: 同上）
- 高齢者が主要利用者で、自治体とも連携するサービス特性から、アクセシビリティを当たり前品質と定義。WCAG 2.2の86基準と各コンポーネントについて、デザインシステムが担保する範囲と、プロダクト／AIエージェントが実装時に担う範囲を明記する（出典: 同上）
- MCPは`get_setup`、コンポーネント一覧・詳細、トークン、デザイン原則、アクセシビリティ、アセット、検索の8ツールを提供する。「目次→必要な詳細」の段階的探索にし、接続時instructionsと最初の`get_setup`呼び出しで、参照忘れやCSS未導入からハードコードへ逃げる経路を塞ぐ（出典: 同上）
- 本体サイトの置換では、AIエージェントの支援でスクリーンリーダー、フォーカス、キーボード操作、強制カラーモード等を約150箇所改善したと報告する。失敗を正しい文書・コンポーネントへ戻すことで、同じ失敗を繰り返さないフライホイールにする（出典: 同上）
- hooksはアクセシビリティやハードコード禁止など100点を要求する決定的な当たり前品質を遮断し、evalsは固定の意図レベル課題でコンポーネント選定や表現を採点する。魅力的品質の創出と、どの品質を仕組みに移すかの判断は人が担う（出典: 同上）
