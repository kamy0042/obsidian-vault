# スペーシングシステム

## 概要

色とタイポグラフィから始めるチュートリアルが多いが、より基礎的で最も間違えられやすい層がスペーシング。「Figma では完璧なのに本番では混沌」の主因は、コンポーネント単体ではなく**コンポーネント間の関係**を設計していないことにある（出典: [[Spacing Systems The Foundation Every Design System Gets Wrong]]）。

## 失敗の型

以下すべて出典: [[Spacing Systems The Foundation Every Design System Gets Wrong]]（Roberto Moreno Celta）

- **コンポーネントファーストの罠**: 各コンポーネントに個別の padding / margin を定義する伝統的手法は、コンポーネントが「レイアウトの中で、他のコンポーネントの隣で」存在する現実を無視する。単体では美しく、組み合わせると混沌になる
- **数学 vs 光学**: 8の倍数などの数学的完全性はしばしば視覚的不均衡を生む。数学的スケールが有効なのはグリッド・コンポーネント内部・実装容易性・大きなページのリズム（線形 4,8,12…／指数 4,8,16…／モジュラー 4,6,9,14,21,32）。光学調整が必須なのはタイポグラフィの行間・アイコンの光学中心・テキストと画像の混合・ブランド要素。解は**ハイブリッド**: 数学的基盤＋文書化された光学的例外（`--space-text-below-heading: 12px` = 数学上の16pxより光学的に締める）
- **静的思考**: モバイル対応は比例縮小ではなく**空間関係が構造的に変わる**（デスクトップは余白がもたらす洗練と認知負荷の低減、モバイルは密度の最大化、タブレットはタッチ考慮のハイブリッド）。タッチターゲット44px・タップ要素間は最低8px

## 関係のマッピングとセマンティックな余白トークン

以下すべて出典: [[Spacing Systems The Foundation Every Design System Gets Wrong]]

- 兄弟関係／親子関係／コンテンツ関係で必要な余白は変わる。コンポーネント種別ペアごとの**関係マトリクス**（Heading→Paragraph はデスクトップ12px・モバイル8px、Card→Card は24px・16px…）を作る
- トークンはサイズではなく**目的**で命名する: `--space-medium`（悪）より `--space-related-elements` `--space-section-break`（良）。ドキュメントも「関連要素には16px」ではなく「**同じユーザー目標に仕える要素には space-related を使う**」と書く
- 階層はトークン一般と同じ3層: primitive（4px…）→ semantic（related / unrelated / section-break）→ component（button-internal-spacing）。文脈適応は `clamp()`（`--spacing-section-break: clamp(32px, 8vw, 64px)`）
- ダークモードは柔らかいコントラストのため、やや広め（×1.1程度）の呼吸が要ることがある

### 関係ベース語彙への反証

Spectrum のデザイナー・エンジニアとの協働調査では、実務者は余白を「強く／弱く関連する」とは表現せず、「ラベルと入力欄の間」「コンテナ内のpadding」のように**配置と構築**で説明した。
関係ベースの語彙は理論的には自然でも、利用者のメンタルモデルと一致しない場合がある。
同チームは反復構造を structural templates として先に定義し、余白トークンを構造から導く方向へ転換した（出典: [[Design tokens need more than semantics]]）。

## 監査と適用

以下すべて出典: [[Spacing Systems The Foundation Every Design System Gets Wrong]]

- 監査フレーム: 単体で均衡か → 異種コンポーネントの組合せで関係が一貫するか → 可変長コンテンツで適応するか → ブレークポイント間で空間関係が意味を保つか。デザイナー（視覚均衡）・開発者（実装の一貫容易性）・コンテンツ（プレースホルダでなく実データ）の三面チェック
- よくある誤り: 選択肢が多すぎる（20+ は覚えられない。**5〜7個のセマンティックな値に絞る**）／コンテンツ文脈の無視／インタラクション状態（hover・focus）の余白挙動の未定義／動的コンテンツを想定しない静的設計
- 実例比較: Tailwind（数学的一貫・学習容易だが意味論と光学を欠く）、Material の 8px グリッド（タッチ考慮はあるが機械的・モバイルで高密度）、Polaris のセマンティック命名（tight / base / loose / extra-loose）
- 「最良のスペーシングシステムはチームが実際に一貫して使うもの。**美的完成度ではなく採用のために作る**」
