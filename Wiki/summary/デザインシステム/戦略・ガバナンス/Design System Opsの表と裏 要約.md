# Design System Opsの表と裏 要約

ソース: [[Design System Opsの表と裏]]

UXPin による解説記事で、元 Shopify Polaris 担当カエリグ・ドゥルモー・プリジェント氏のウェビナーを基に、デザインシステムの運用を標準化・最適化する「Design System Ops」を紹介する。
Design System Ops はデザインと開発の両分野にまたがり、コンポーネントのデザインからリリースまでのプロセスを整えて「決断疲れ」を減らし、デザインシステムチームが創造的な仕事に時間を使えるようにする役割である。
具体的にはデザインハンドオフでのアセット変換基準、ローカル開発環境やリンターの整備、視覚的回帰テストやアクセシビリティテストの自動化などでエンジニアの意思決定を減らすことを目指す。
進め方は、ユーザー（デザイナー・エンジニア）の調査、問題の特定、解決策の実施、ビルドタイム・MTTR・品質などの指標による測定という4段階で、誰でも始められる。
「成功は配置したツールではなく解決した問題によって測られるべき」であり、Ops の本質はツール導入ではなく非効率の発見と修正だと結論づける（末尾は UXPin Merge の宣伝を含むベンダー記事である点に留意）。
