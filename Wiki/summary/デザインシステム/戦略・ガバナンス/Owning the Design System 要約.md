# Owning the Design System 要約

ソース: [[Owning the Design System]]

Adobe の Photoshop と Illustrator で Escape キーの挙動が逆という逸話から、デザインシステムは「完成させるプロジェクト」ではなく「継続的に所有する機能（function）」だと論じる。
6ヶ月で納品→チーム解散→3年後に「今度こそ本物を」の再出発という「プロジェクトの罠」を最大の失敗モードとし、名前を持つ一人の責任者（委員会ではない）を org チャートに置き、システムの健全性で評価せよと主張する。
配置は Design 直下（エンジニアリング側の責任者不在で最悪になりがち）でも Platform Engineering 直下（デザイン品質が犠牲）でもなく、プロダクトライン責任者と対等なピアが望ましいとする。
健全性は Adoption（使われているか）・Throughput（システム利用で出荷が速いか）・Completeness（使いたいときに使えるか）・Downstream value（複利的効率）の4指標で計測し、フォーク発生時に道徳的非難ではなく診断的対応を可能にする。
エージェント時代にはドリフトの速度も上がるが、ハーネスと agent 向けツール（MCP サーバー、スキル）を備えたシステムは逆にエージェント開発を加速し、持続的優位を複利化すると指摘する。
