# SmartHR UI を中心としたエコシステムのすすめ - SmartHR Tech Blog 2 要約

ソース: [[SmartHR UI を中心としたエコシステムのすすめ - SmartHR Tech Blog 2]]

SmartHR のプロダクトデザイナー @uknmr による記事で、SmartHR UI の目的を「UI を揃えること」ではなく「SmartHR というプロダクトの開発を最速で進めること」と再定義する。
SmartHR UI は4年以上、専任チームではなく各プロダクトを担当する有志の兼任で開発されており、「必要なものを必要なだけ作る」姿勢と、現場の課題を感じた張本人が速度を保ったまま開発できる点を兼任の強みとして挙げる。
SmartHR UI・デザインシステム・スマパタ（SmartHR Patterns）・各プロダクトが相互に関係し合う「エコシステム」が存在し、1つのプロダクトで発生した課題を SmartHR UI で解決すれば数十の他プロダクトやグループ会社・サードパーティにも伝搬すると論じる。
このエコシステムは開発者が「使うこと」から回り始めるため、貢献の第一歩は使うことであり、フィードバックが増えるほどコンポーネントライブラリの質が高まる。
さらに具体的な貢献パターンとして、直接コミット、新機能開発時のフィードバック（`ui/index.ts` による出荷待ち管理の工夫を含む）、スクラムでの課題解決、専任化の4つを提示する。
