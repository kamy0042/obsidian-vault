# デザイナーと開発者の連携を効率化するデザイントークンとは何か？  アドビUX道場 UXDojo 要約

ソース: [[デザイナーと開発者の連携を効率化するデザイントークンとは何か？  アドビUX道場 UXDojo]]

Adobe Blog によるデザイントークンの入門記事。
トークンは UI スタイル値を表すデザインシステムの最小単位であり、`$blue-400` のような単なる変数との違いは「その値がどう使われるか」という情報を名前が持つ点（例: `$button-cta-background-color = $blue-400`）だと整理する。
利点として、一箇所の更新が全関連箇所に波及する柔軟性、プラットフォーム間の一貫性（Web は HEX、iOS は RGBA など形式変換も可能）、npm パッケージ等による開発プロセスの効率化を挙げる。
管理のベストプラクティスとして以下を推奨する。

- インターフェイスインベントリでデザインを最小単位に分解する
- 「X回使われている」などトークン化の基準を定義する
- **[カテゴリ]-[タイプ]-[アイテム]-[ステート]** 形式の命名規則を先に決める
- JSON 格納で複数プリプロセッサに展開可能にする
- 提案は誰でも・承認は責任者というワークフローを敷く
- カラーは WCAG のコントラスト基準（4.5:1 / 3:1）を検証する

適切に管理されたトークンはデザイン決定を迅速にし、デザイナーと開発者が一貫性と拡張性のある UI を協業で実現する基盤になると結ぶ。
