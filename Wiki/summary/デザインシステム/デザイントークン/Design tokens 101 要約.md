# Design tokens 101 要約

ソース: [[Design tokens 101]]

Mae Capozzi によるデザイントークン入門（邦訳クリップ）。
トークンを「色・タイポグラフィ・間隔などのスタイル属性を事前定義された構造で保存する手法」と定義し、Salesforce の Jina Anne を発明者として紹介する。
サイトのトークン成熟度を「トークンなし → 非構造化トークン → 構造化トークン」の3レベルに整理し、`babyBlue` のような値ベースの名前はリブランド時に破綻するため、デザイナーと開発者が形と命名規則に合意した構造化トークンを理想とする。
リデザイン・デザイナーと開発者の協働・テーマ設定・UI一貫性という4つのワークフローをレベル別に比較し、構造化トークンがいずれでも最も優位だと示す。
企業が複数アプリを持つ段階では共通のトークン仕様の策定が有効で、テーマ可能なフロントエンドや Figma からコードへの自動反映などの利点があるとし、Brent Jackson の Theme UI を先行例に挙げる。
