# コンポーネントレベルのデザイントークン：価値はあるか？  Nate Baldwin  Medium 要約

ソース: [[コンポーネントレベルのデザイントークン：価値はあるか？  Nate Baldwin  Medium]]

Nate Baldwin が Adobe Spectrum での実体験をもとに、コンポーネントレベルトークンの費用対効果を検証する記事。
利点はデザインの実装保証（7+ フレームワークの一貫性を担保）、パッチ変更の全フレームワークへの伝播、`button-cta-background-color-hover` のような自己記述的名前によるセルフサービス、そして VRT やコード生成などの自動化基盤になること。
一方で落とし穴は深刻で、全属性×全状態の組み合わせでトークンが指数的に増殖し（Spectrum は一時 21万トークン・18MB の JSON）、`spectrum-button-m-warning-quiet-overbackground-textonly-focus-ring-animation-duration` のような名前が認知負荷を破壊し、トークン名が API になるため t-shirt サイズ追加のような設計変更が全トークンの破壊的変更になった。
完全なコンポーネントレベル運用が割に合うのは「4+ フレームワーク支持・中央集権チーム・単一デザイン言語・プラットフォーム均一・専任ツーリングチーム」の5条件が揃う場合のみで、大半のチームは必要な箇所に少数使うのが良いと結論づける。
真の価値はトークンそのものより「正しいトークンへたどり着くための指示書」という思想にあり、静的な key-value を超えた軽量で相互運用可能な新形式が必要だと展望する。
