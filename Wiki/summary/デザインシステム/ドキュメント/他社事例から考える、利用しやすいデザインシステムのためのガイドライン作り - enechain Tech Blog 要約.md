# 他社事例から考える、利用しやすいデザインシステムのためのガイドライン作り - enechain Tech Blog 要約

ソース: [[他社事例から考える、利用しやすいデザインシステムのためのガイドライン作り - enechain Tech Blog]]

enechain のデザイナーが、Figma と実装の乖離を機に「デザインガイドラインとしてのデザインファイル・ドキュメントのあるべき姿」を他社事例から調査した記事。
調査対象は3つで、デジタル庁デザインシステム（v1 は Figma にガイドラインを集約、v2 で Web サイトへ分離）、GitHub Primer（Figma はコンポーネント集に徹し、Web サイトにガイドラインと UI patterns が充実）、Ameba Spindle（Figma と Web の両方にガイドライン、各コンポーネントにアクセシビリティ項目を併記）。
比較の結論として、大規模なデザインシステムほど Web サイト側にガイドラインが集約される傾向があり、中小規模ならデジタル庁 v1 や Spindle のように Figma 上にコンポーネントとガイドラインを集約する方が情報が分散せず運用しやすいとする。
enechain ではこれを受けて Figma をセクション区切り・概要文・変更履歴つきで整理し、詳細な OK/NG 例は Notion のガイドラインページに置く構成に改善した。
