# デザインシステムの注釈、パート1 アクセシビリティ 要約

ソース: [[デザインシステムの注釈、パート1 アクセシビリティ]]

GitHub の Accessibility Design チームによる、アクセシビリティ注釈（annotations）とデザインシステムを統合した事例（2部作の前編）。
「アクセシブルなコンポーネントを使えばアクセシブルなデザインになる」は誤解であり、見出し階層の破綻・文脈依存の代替テキスト・フォームのエラーメッセージなど、コンポーネント単体では防げない障壁が本番に流出すると指摘する。
注釈は視覚に現れない設計意図（フォーカス管理、支援技術のナビゲーション等）を明示化し、手戻りや監査指摘を防ぐが、従来の注釈キットでは組み込み済みの仕様まで冗長に注釈する手間が発生していた。
そこで GitHub は Primer コンポーネントごとに「インスタンス間で変わる項目だけ」を穴埋め式で記入する Preset annotations を開発し、監査指摘の多い10コンポーネントに適用した。
各 Preset はコンポーネントドキュメントや Storybook にリンクされており、注釈の工数削減・デザインシステム採用の促進・専任者不在チームへの支援を同時に実現している。
