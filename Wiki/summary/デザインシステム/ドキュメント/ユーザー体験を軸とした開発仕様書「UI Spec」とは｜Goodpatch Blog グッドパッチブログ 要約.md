# ユーザー体験を軸とした開発仕様書「UI Spec」とは｜Goodpatch Blog グッドパッチブログ 要約

ソース: [[ユーザー体験を軸とした開発仕様書「UI Spec」とは｜Goodpatch Blog グッドパッチブログ]]

Goodpatch が MVP のアジャイル開発向けに用いる仕様書「UI Spec」の解説と実践例。
画面ごとに機能要件を書く一般的な仕様書と異なり、ユースケース（誰が・なにを・どうするか）をベースにするため仕様が機能単位で分散せず、届けたい価値の共通認識を保ったまま優先順位づけと開発ができる。
開発途中の仕様変更を前提とし、変更点・変更日・理由を追記していくことで、デザイナーとエンジニアのコミュニケーション記録としても機能する。
実プロジェクトでは、ユースケース作成 → プロトタイプ → 優先順位づけ → UI Spec 作成 → 全員レビュー → スプリントという手順で運用し、Notion でステータス管理して Figma と相互リンクした。
確認漏れ防止・仕様変更経緯の共有・ユースケースに沿った成果物レビューと QA・価値の共通認識という効果が得られたが、項目や手順はチームに合わせてアレンジすべきと結ぶ。
