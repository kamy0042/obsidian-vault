# タイミーでは先鋭的なDesignDataOpsを構築した｜Yasuhiro Yokota 要約

ソース: [[タイミーでは先鋭的なDesignDataOpsを構築した｜Yasuhiro Yokota]]

少数精鋭のタイミーが、デザインデータのガバナンスと完全性を確保する取り組みを「DesignDataOps」と名付け、自動化・仕組み化を徹底的にやり込んだ事例。
具体的な仕組みは4つ。

- Figma Variables → 中間リポジトリ → Style Dictionary → 各プラットフォーム（Swift/Kotlin/TypeScript）へ PR を自動作成するデザイントークン自動配信機構
- Variable Mode の「os」変数で iOS/Android のタイポグラフィやネイティブコンポーネントを一括切り替え
- 命名規則・旧スタイル置換・ユビキタス言語チェックなどをボタン一発で実行する自社製 Figma Normalizer Plugin
- Figma のコンポーネント・画面情報を毎晩 Notion に同期し依存関係を俯瞰できる自動同期

レギュレーションは自動化と同時に設計しないと運用に無理が出るとし、「限界費用をゼロにできるがゆえに初めて運用可能になるレギュレーションがある」と指摘する。
仕組み化は組織が大きくなってからではなく、少人数のうちから先鋭的に取り組むべきで、増員後のキャッチアップコスト低減や中規模化後のガバナンス強化コストの先回りになると結論づけている。
