# SmartHRのプロダクトデザインの生産性を高める“デザイン”のためじゃないデザインシステムとは（Schema2022）｜wentz｜note 要約

ソース: [[SmartHRのプロダクトデザインの生産性を高める“デザイン”のためじゃないデザインシステムとは（Schema2022）｜wentz｜note]]

Schema by Figma 2022 Tokyo での発表を元に、SmartHR Design System を「デザイナーのため」ではなく開発全体の生産性のための手段として位置づける講演記事。
SmartHR ではデザイナーが各開発チームに所属する開発者であり、デザインとエンジニアリングが不可分である以上、デザイン業務だけの効率化は部分最適にしかならないという前提に立つ。
デザインシステムは「妥当な意思決定を早めるための補助線であって法律ではない」とされ、“デザインシステム警察”は存在せず、ガイドラインに従うかは開発チームの判断に委ねられる。
現場ではモブデザインや「用字用語リクエスト」の Slack ワークフローで職能横断の議論を行い、実装と一致する Figma ライブラリ（SmartHR UI）が非デザイナーの参加ハードルを下げている。
専任オーナーは置かず、各担当者が課題ベースでガイドラインを積み上げる体制を、テンプレート・GitHub PR レビュー・Figma ブランチ機能などの仕組みで支えており、「デザインシステムは銀の弾丸ではなく、顧客に素早く価値を届ける手段に過ぎない」と結ばれる。
