# Establishing a Single Source of Truth OneSignal’s Journey with Supernova – Blog – Supernova.io 要約

ソース: [[Establishing a Single Source of Truth OneSignal’s Journey with Supernova – Blog – Supernova.io]]

通知プラットフォーム OneSignal がデザインシステム「Beam」のドキュメント基盤に Supernova を採用した事例（Supernova 自身によるケーススタディ記事）。
以前は Figma と Storybook Addon Docs で運用していたが、Storybook はビルドが遅く「ドキュメントのためのコンポーネントライブラリ」を PR 経由で作る高コスト運用になっていた。
Head of Design の Lee Munroe は「デザインシステムは Figma ファイルではなく、Figma とフロントエンドコンポーネントを結びつけるドキュメントを含む総体」と述べ、Figma / Storybook 統合を理由に Supernova を選定した。
導入によりプロジェクトあたり数時間〜数日の削減、質問往復の減少、1回1時間×週数回かかっていた新人オンボーディングの自動化が得られたとする。
四半期ごとのアンケートと Google Analytics 連携で利用状況を計測し、今後は Figma のトークン変更からコード PR を自動生成する計画。
ベンダー自身の宣伝記事である点は割り引く必要があるが、「ドキュメントが Figma とコードを束ねる」という主張は実務的な教訓になる。
