# デザインシステムは「タネ」から育てる。「カナリークラウド」Figmaマスターデータ設計の裏側｜Cocoda 要約

ソース: [[デザインシステムは「タネ」から育てる。「カナリークラウド」Figmaマスターデータ設計の裏側｜Cocoda]]

急成長する不動産 SaaS「カナリークラウド」で、入社1ヶ月のデザイナーがデザインシステムの「タネ」として Figma マスターデータ整備に取り組んだ事例。
UI リニューアルから入るのではなく、あえて現状の負債（見た目の異なる同役割コンポーネント等）を残したままマスターデータ化し、理想設計は別途可視化する二段構えで、機を見て UI 改善につなげる設計にした。
命名は汎用コンポーネントを第一階層に、単体で使わないものは「Parts」階層に分離し、Atlassian を参考にした Slot と Swap instance で Detach 不要のコンポーネント構造を実現している。
浸透面では、設計判断や NG パターンをすべてドキュメント化し、「デザインがつくれるようになる勉強会」というコンセプトの Figma 勉強会で開発メンバーへの活用を促した。
約1ヶ月でデザイン作業の効率が向上し開発メンバーの UI 改善意識も高まり、デザインシステム化プロジェクトの発足につながったことから、グロースフェーズでは改修の土壌づくりをファーストステップにすべきと結論づけている。
