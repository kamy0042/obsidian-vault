# 「デザインシステム」がよくわからないので、理解の仕方を変えてみる｜usagimaru 要約

ソース: [[「デザインシステム」がよくわからないので、理解の仕方を変えてみる｜usagimaru]]

usagimaru が「デザインシステム」という語の曖昧さと、巷の解説が DS を「便利な UI コンポーネント集（レゴセット）」に矮小化している現状を批判する論考。
Nathan Curtis の原定義は「コンポーネント集・まとまりのある製品群・協調する組織」の3点セットなのに、Wikipedia や多くの解説からは製品間の連関と組織の要素が抜け落ちていると指摘する。
そのうえで独自の再解釈として、DS（仮）を3要素に分けて捉え直す:
- デザイン言語（設計思想・コンセプト・ガイドライン・語彙による共通理解）
- ツールボックス（デザイン言語に基づく道具・共通部品のライブラリ。
UI コンポーネントライブラリはここ）
- 組織（デザイン言語とツールボックスを運用する環境と人々）
Apple は HIG（1970年代から編纂）・WWDC での対話・SDK という形で、「デザインシステム」と呼ばれる40年も前から同じ実践をしてきたと例証する。
結論として、「デザインシステムを作る」とは UI コンポーネントライブラリを整えて終わりではなく、言葉や組織という目に見えない構造まで含めた広い視野で取り組むべきものだとする。
