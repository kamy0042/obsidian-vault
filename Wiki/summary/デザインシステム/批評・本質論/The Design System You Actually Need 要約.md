# The Design System You Actually Need 要約

ソース: [[The Design System You Actually Need]]

Han が「誰も使わない DS に6ヶ月費やしたチーム」と「12コンポーネントの共有 Figma ファイルでシリーズBまで走ったスタートアップ」を対比し、「どう上手く作るか」の前に「今実際に何が必要か」を問えと説く記事。
Shopify や GitHub の模倣を「彼らの問題への解決策の形」と退け、過剰設計を生むバイアスを列挙する:
- ベストプラクティスバイアス（最善未満＝間違いという誤解）
- 生存者バイアス（成功した有名 DS しか研究されない）
- 複雑性バイアス・早すぎる抽象化
- 社会的証明（「Stripe がやってるから」）
チーム規模・製品数・使える時間・「今一番痛いもの」の4問で必要物を決め、製品1つ・チーム5人ならトークンより命名された CSS 変数で十分と具体例を示す。
方向性は「横に広げず上に伸ばす」——コンポーネントを増やすより、実際に使われる5つに深さ（アクセシビリティ・ガイドライン）を足す。
成熟度は5段の梯子（共有された決定→コンポーネント→言語→プロセス→エコシステム）で、多くのチームは1〜3段で十分であり、シンプルさは学んだときに変更しやすい形だからこそ価値があると結論づける。
