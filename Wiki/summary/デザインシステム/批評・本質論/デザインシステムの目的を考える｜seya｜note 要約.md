# デザインシステムの目的を考える｜seya｜note 要約

ソース: [[デザインシステムの目的を考える｜seya｜note]]

seya が「一貫性のため」「生産性のため」という通説的な DS の目的を解像度高く再検討した論考。
結論の定義は「デザインの意思決定の統一と、明確な目的によって定義されユーザに検証されたパターンで作られる一貫性を手段として、『ユーザの認知負荷の軽減』『再利用性』という品質を上げ、デザインのスケーラビリティを実現するため」。
一貫性については、認知負荷軽減に効く一方で目的の異なる UI を無理に揃えると逆効果になる（Consistency Considered Harmful）ため、目的別にパターンが分割され、実際のユーザーで検証されていることが前提だとする。
既存プロダクトと別文脈で理想だけで作られた DS が使われなくなる「デザインシステム墓場」の典型例を自身の経験から描く。
生産性は「車輪の再発明のコスト」と「DS 自体のメンテナンスコスト」の差分で考えるべきで、プロダクト数・人数が多いほどレバレッジが効く＝スケーラビリティこそが DS の本質的な性質だとする。
組織で働く人とコミュニケーション（ハブ&スポーク、Salesforce の Cyclic Model）もシステムの一部と捉えるべきで、DS の悩みの9割方はコミュニケーション課題だと締めくくる。
