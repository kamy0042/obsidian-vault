# Building language for design systems 要約

ソース: [[Building language for design systems]]

デザインとエンジニアリングが「同じ言語を話す」とは、語彙と文法（命名・合成規則・variant/state/status といったカテゴリ）を共有し、同じ語彙表に対して解決することだと定義する。
語彙は「継承」（フレームワークから無償で得るが、強制はコード境界で止まる）か「著作」（自作するが、強制の負担も自前になる）のいずれかで到来し、ハンドオフの揺らぎは両者が同じ対象を別言語で記述することに起因する。
デザイントークンは著作語彙の強制に成功した先例であり、DTCG 仕様による標準化が「著作の負担を継承に変換する」成熟経路を示した。
一方 props はフレームワーク依存のため標準化が構造的に不可能で、実測では88コンポーネントから200超の props と10件のドリフト（type/variant の混在、outline/outlined/bordered 等）が見つかり、機械可読な語彙表（prop map）を読み取るエージェントが唯一の橋になると論じる。
デザインシステムチームはデザインにもエンジニアリングにも属さず、何を継承し何を著作しどう強制するかという「言語の決定」を保持する両者の界面だと結論づける。
