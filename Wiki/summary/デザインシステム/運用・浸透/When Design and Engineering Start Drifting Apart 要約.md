# When Design and Engineering Start Drifting Apart 要約

ソース: [[When Design and Engineering Start Drifting Apart]]

デザインと実装のドリフトは、未対応の要件に対する Figma variant、追加 prop、wrapper、ローカル実装といった合理的な小判断が同期されないまま蓄積して起きる。
問題は部品が増えることだけでなく、API、実装、テスト、文書、変更判断を重複して支払い続け、やがてシステムへの信頼を失うことにある。
コンポーネントを入力・状態・制約・振る舞い・互換性を持つ API として扱い、デザインとエンジニアリングが契約を共同で形作るべきだと提案する。
ローカルな例外は許容しても、それを共有システムへ戻すか再検討するループを持ち、逸脱を無自覚な drift ではなく意図的な decision にする必要がある。
目標は Figma とコードの完全同期ではなく、差分を可視化し、意図を説明でき、容易に修正できる状態と、両職能の共通メンタルモデルを保つことだと結論づける。
