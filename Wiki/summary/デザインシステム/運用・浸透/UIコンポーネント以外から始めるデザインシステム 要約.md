# UIコンポーネント以外から始めるデザインシステム 要約

ソース: [[UIコンポーネント以外から始めるデザインシステム]]

長谷川恭久が、デザインシステムを「プロダクトをデザインするための仕組み作り」と捉え直すと UI コンポーネント作成より大事なことが見えてくると説く記事。
UI コンポーネントは事業目標・プロダクトの価値・指標・意思決定という積み上げの上に成り立つ表層的な解決手段であり、この関係性を無視してライブラリを揃えても「作ってみたけど浸透しなかった」に終わると指摘する。
プロダクトの価値が明文化されていなければコンポーネントの良し悪しは「一貫性がある」以上の判断ができないため、PM とのビジョン明文化やストーリーマッピングから始めることを勧める。
ガイドラインも同様に、デザインドキュメントを書く習慣のない組織でいきなり書くのは困難で、レビュー時の言語化など基本から始めるべきだとする。
一貫性のある UI ライブラリより、メンバーの「良いプロダクト」への視点の一貫性の方が組織への貢献度が高いと結論づける。
