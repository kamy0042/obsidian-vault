# The Hardest Part of Design Systems Was Never Components 要約

ソース: [[The Hardest Part of Design Systems Was Never Components]]

Design Systems Collective の記事。
DS の議論はコンポーネントから始まりがちだが、コンポーネント構築は時間さえあれば解決可能な技術問題であり、本当の困難はシステムが存在し複数チームが使い始めた後の「人・調整・組織横断の採用」にあると主張する。
各チームの局所最適な逸脱（コンポーネントの改変、独自再実装、新パターン要求）は悪意なく蓄積し、DS が提供するはずだった一貫性を蝕む。
その段階で DS チームの仕事は UI 制作から社内教育プログラムの運営（ワークショップ、オフィスアワー、質問対応）へとシフトし、組織全体を見渡した優先順位付けと、「なぜその要求が今できないのか」を説明する透明性が信頼構築の鍵になる。
一貫性と柔軟性のバランス調整も続き、最良のシステムはコンポーネント数が多いものではなく、強い基盤を提供しつつチームの革新を許すもの。
DS チームは組織内のコネクタ（橋渡し役）へと進化し、最も難しい仕事は「組織全体が共有・協調した形でプロダクトを作れるようにすること」だと結論づける。
