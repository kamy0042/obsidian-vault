# デザインシステム開発優先度の「難しさ」と「対策」｜hikaru-takase -Loglass｜note 要約

ソース: [[デザインシステム開発優先度の「難しさ」と「対策」｜hikaru-takase -Loglass｜note]]

Loglass のデザイナー高瀬氏が、デザインシステム導入の「開発優先度が上がりにくい」という現実への対策を実践知として整理した記事。
機能開発との投資対効果比較で負けやすい DS を進めるには、「事業のスケールにおいて DS が必要」というビジネス観点を軸に「デザインシステムの自治権」を認めてもらう活動が必要だと説く。
具体的には (1) 長すぎるボタンやトーストの誤用など現場の課題感をデザイン doc で共有、(2) マルチプロダクト化などの少し未来の事業課題に紐づけて「今やらないとヤバい」状態を作る、(3) ボトムアップで小さく作り始める、(4) 早期にフロントエンドエンジニアを巻き込む、(5) 実装優先度を PdM・エンジニアと議論して合意する、の5つを挙げる。
特に (2) では Figma ファイル構成がプロダクトに密結合していた状態を、トークン層を切り出した構成に再設計する提案を事業スケールの文脈で通した。
自治権が得られると「答えは doc にある」状態に近づき、各所から相談や優先度要望が寄せられる好循環が生まれると結論づけている。
