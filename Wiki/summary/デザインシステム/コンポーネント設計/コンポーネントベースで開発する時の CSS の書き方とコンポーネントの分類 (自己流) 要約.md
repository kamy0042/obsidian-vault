# コンポーネントベースで開発する時の CSS の書き方とコンポーネントの分類 (自己流) 要約

ソース: [[コンポーネントベースで開発する時の CSS の書き方とコンポーネントの分類 (自己流)]]

mizchi 氏による、React/Svelte 時代の CSS 設計の自己流ノウハウ。
React コンポーネントの管理単位と CSS レイアウトの管理ポリシーを完全一致させる前提で、コンポーネントを4種に分類する。

- ロジックコンポーネント: Provider や hooks のみで CSS も DOM 実体も持たない
- レイアウトコンポーネント: grid/flex で領域分割し子の配置のみを責務とする（レスポンシブもここ）
- ブロックコンポーネント: `width/height: 100%` で与えられた領域を埋める交換可能な要素
- インラインコンポーネント: コンテンツでサイズが決まる要素

結果として Root → Layout → Block → (Inline or Layout) の繰り返し構造になり、CSS 属性から種類が自然に分類され、配置変更・レスポンシブ・スケルトンスクリーン実装に強くなる。
一方でリキッドレイアウトの height 継承ポリシーを保ちづらい、ブロックが overflow しやすいなどのデメリットも明示している。
