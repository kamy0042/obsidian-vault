# 再利用可能なコンポーネントはアンチパターン - ジンジャー研究室 要約

ソース: [[再利用可能なコンポーネントはアンチパターン - ジンジャー研究室]]

「コンポーネントは再利用可能に設計すべき」という論調に YAGNI の立場から真っ向反対する2016年の古典的議論。
普通にアプリケーションを作ると「アプリケーションを知っている（＝再利用不可能）」コンポーネントが圧倒的に多く、疎結合化を目指すと Model と Action の引数が際限なく増えるバケツリレーに陥る。
DatePicker の例では、権限・ユーザー別のカスタマイズ要求が積み重なり、見た目は疎結合でも実質特定アプリ専用になる上、コンポーネント内の状態がグローバルに持つべきデータと重複する問題も生じる。
モデルとビューは8割方同じ関心を持つため、残り2割のために疎結合の前提が崩壊するのが構造的な原因だと分析する。
共通化すべきは「見た目」であり、データを表示するだけのシンプルな関数としてのビューに留め、巨大なモデルやアクションは恐れず受け入れてアプリケーションの本質に時間を使えと結論づける。
