# デザインシステムの議論はデザイナーとエンジニアで分岐した？ 抽象度の高いコンポーネントライブラリの弊害 要約

ソース: [[デザインシステムの議論はデザイナーとエンジニアで分岐した？ 抽象度の高いコンポーネントライブラリの弊害]]

アトミックデザイン的な階層を導入せず「コンポーネント」一層ですべてを定義する近年の運用（デジタル庁・SmartHR 等）への問題提起。
階層議論はエンジニア視点（ソフトウェアアーキテクチャ）とデザイナー視点（ブランド伝播）で分断され、全パーツが抽象化されると「ドメインロジックに紐づいた再利用可能コンポーネントの不在」が生じ、同じコンポーネントを使ってもレイアウトが微妙に違う画面が増えると指摘する。
代替として Heavyweight 社（2017）の階層を現代的に再解釈した Identity（=デザイントークン）/ Elements / Components / Compositions / Layouts / Pages の6階層を提案する。
特に Compositions はユースケース別のドメインロジック（登録フォームと調査フォームのボタン配置差など）を定義する層、Layouts はグリッド等のレイアウト自体をコンポーネントとして再利用する層で、これらの不在が一貫性の穴になるとする。
デザイナー視点でも階層構造のメリットは無視し難く、導入の再検討を促して締めくくる。
