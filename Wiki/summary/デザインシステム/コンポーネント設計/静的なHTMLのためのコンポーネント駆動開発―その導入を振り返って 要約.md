# 静的なHTMLのためのコンポーネント駆動開発―その導入を振り返って 要約

ソース: [[静的なHTMLのためのコンポーネント駆動開発―その導入を振り返って]]

React 等を使わない静的 HTML/CSS 納品のプロジェクトにコンポーネント駆動開発（CDD）を持ち込んだ Shiftbrain スタンダードデザインユニットの振り返り。
KSS などの CSS ベースのスタイルガイドツールはライブリロードやデータ書き換えに欠けるため、プレーン HTML をストーリーにできる Storybook へ移行し、Pug の mixin をコンポーネント定義に採用、自作パッケージ Storypug で開発体験を整えた。
これにより Pug / JS / SCSS / ストーリー / テストを1フォルダにまとめるコンポーネント基準のプロジェクト構成が可能になり、Knobs アドオンでバリエーションの組み合わせテスト、Stimulus コントローラーとの連携で JavaScript インタラクションも個別開発できる。
Jest のスナップショットテストでストーリーをそのまま描画検証に流用できる点も利点として挙げる。
成果はデザイナー・PM への早期プレビュー共有、バックエンド開発者のベンチマーク、ステークホルダーへの進捗可視化などチーム全体に及び、Pug に限らず任意のテンプレートエンジンに適用可能な手法だと結論づける。
