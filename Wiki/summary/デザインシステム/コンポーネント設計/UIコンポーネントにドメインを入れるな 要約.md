# UIコンポーネントにドメインを入れるな 要約

ソース: [[UIコンポーネントにドメインを入れるな]]

汎用 UI コンポーネントにデータロジック等のドメイン知識を混入させるなと説く設計論。
数値表示 UI を CalorieStat・GradeStat のようにドメイン別に量産する誤った抽象化を示し、label / value / unit を受け取る汎用 Stat コンポーネントを土台にドメインマッピングを上に重ねる正しい抽象化と対比する。
実装は「モノリシックタイプ」（簡単だが拡張性に乏しい）と「合成タイプ」（Compound Components 的にマークアップ構造を可視化し、スタイルだけ受け継いだ HTML を組み立てる）に分類され、堅牢性と柔軟性を求めるなら後者を推す。
ただし程度問題であり、UserProfile のような業務特化コンポーネントはドメイン知識を含んでよく、Button や Table などの UI ライブラリ級の汎用部品は絶対に含めるべきでないという3段階の判断基準を示す。
根幹となる UI を抽象化しないのは設計の怠慢であり、バックエンドで DB 接続から API 出力まで一纏めに書く行為と同じくらい重大だと戒める。
