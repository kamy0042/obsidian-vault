# コンポーネントを配信するシステムについて構想する 要約

ソース: [[コンポーネントを配信するシステムについて構想する]]

Cloudflare の Fragment Piercing から着想を得た、npm を経由しないコンポーネント配信システムの PoC 構想。
デザインシステムの一般的な npm ライブラリ配信には「変更反映までの速度とコスト（利用側のアップグレード・再デプロイが必須）」「技術スタックギャップとバンドルサイズ」の2つの課題があると整理する。
提案は、コンポーネントを個別にホスティングして SSR し、エッジ（Cloudflare Workers 上の Piercing Gateway）でベースページの HTML に DOM を結合する方式で、利用側の反映コストをほぼゼロにする。
コンポーネントは書き慣れた React で実装し、Qwik の qwikify$ でラップして選択的ハイドレーションを行うことで、利用側の技術スタックに依存せずクライアントのフットプリントを最小化できる。
サンプルシステムの構築と実験は完了済みだが、テスト・パフォーマンス・運用保守の課題が山積みで、UI コンポーネントよりもフィーチャーコンポーネントの埋め込み（ショートコード的用途）に向くと自己評価している。
