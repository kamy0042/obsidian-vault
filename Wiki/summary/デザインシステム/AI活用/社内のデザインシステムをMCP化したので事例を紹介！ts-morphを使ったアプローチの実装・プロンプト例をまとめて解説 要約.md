# 社内のデザインシステムをMCP化したので事例を紹介！ts-morphを使ったアプローチの実装・プロンプト例をまとめて解説 要約

ソース: [[社内のデザインシステムをMCP化したので事例を紹介！ts-morphを使ったアプローチの実装・プロンプト例をまとめて解説]]

エス・エム・エスが Ubie の事例に触発され、Chakra UI ベースの社内デザインシステムを MCP 化した実装詳細の解説記事。
LLM に提供すべき情報を「デザイントークン」と「コンポーネント定義（Props の型）」の2つと定め、トークンは Chakra UI の theme オブジェクトを JSON 化して複数種類まとめて取得できるツールとして提供する。
コンポーネント定義は ts-morph で型情報を展開・構造化して提供する手法を採用し、循環参照や深いネストに対応する extractType / resolveObject / serializable の実装例を公開している。
Figma MCP は野良実装のリスクと、デザインシステム連携に重要な componentProperties が GLips/Figma-Context-MCP で取得できないことを理由に内製した。
MCP は設定しただけでは使われないためプロンプトとセットで社内宣伝することが重要とし、AST から情報を提供する手法はトークン効率と正確性に優れると総括、将来的には非エンジニアが自然言語で軽い開発をできる環境を目指す。
