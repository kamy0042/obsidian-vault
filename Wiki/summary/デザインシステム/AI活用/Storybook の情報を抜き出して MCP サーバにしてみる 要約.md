# Storybook の情報を抜き出して MCP サーバにしてみる 要約

ソース: [[Storybook の情報を抜き出して MCP サーバにしてみる]]

LayerX バクラク事業部のスタッフエンジニアが、Ubie の「社内デザインシステムを MCP サーバー化したら UI 実装が爆速になった」に触発され、社内共通 UI コンポーネントの Storybook を情報ソースに MCP サーバを試作した記事。
全コンポーネントの詳細を一度に返すと情報がぼやけるため、一覧取得ツールと個別詳細取得ツールの2つに分ける設計（REST の List/Get 分割と同じ考え方）を採った。
一覧は Storybook が内部でフェッチする index.json を加工して返し、詳細は Storybook の Props ドキュメント生成を支える react-docgen(-typescript) を使って TSDoc コメントや型情報を抽出して返す。
やっつけプロトタイプでも Cursor Agent がコンポーネントの Props や使い方に正しく答えられるようになり、AI 開発支援の恩恵を十分に感じられた。
デザインシステムだけでなくドキュメント・コードコメント・Storybook といった資産が、AI 時代には従来以上に開発生産性を高めるツールになると考察している。
