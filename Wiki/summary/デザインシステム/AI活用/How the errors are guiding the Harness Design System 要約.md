# How the errors are guiding the Harness Design System 要約

ソース: [[How the errors are guiding the Harness Design System]]

Harness Design System の John Morais が、Claude Code にコードで実インターフェースを作らせた際の失敗パターンから、ドキュメント整備の優先順位を導く手法を報告する。
テーブルやメニューなど世間に広く存在するグローバルパターンのコンポーネントは LLM がうまく構築できる一方、プロダクト固有のコンポーネント（ドロワー、ステータス表示等）では「見つからないと勝手に発明する」失敗が集中した。
LLM の発明はドキュメントの欠落箇所を正確に示す地図であり、何を文書化すべきか計画する必要はなく、LLM に失敗させてその誤りを優先順位付けに使えばよいと主張する。
ただし失敗の原因がコンポーネント未発見・ドキュメント不足・指示の誤りのいずれかは切り分けが必要で、古いトークンなど基盤の問題は AI レイヤーを載せる前に解決すべきと順序を強調する。
チームは2週間の集中期間でトークンのコード適用、アンカースクリーンのコンポーネント精緻化、ドロワー失敗の解明を目指している。
