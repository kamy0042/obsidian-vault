# 属人化させないデザインルール管理。ログラスの「AI駆動のデザインシステム運用フロー」について｜Cocoda 要約

ソース: [[属人化させないデザインルール管理。ログラスの「AI駆動のデザインシステム運用フロー」について｜Cocoda]]

ログラスのデザイン部による、AI 駆動のデザインシステム運用ワークフロー構築の事例紹介。
コンポーネントライブラリを読み込ませるだけの LLM UI 生成は「デザインルールを LLM が理解していない」ため実務レベルに至らず、コンポーネントの扱い方を場合分けしたドキュメントが鍵だと気づいたが、人手で網羅的に作るのは限界があるため「デザインルールのドキュメント自体を AI に作らせる」仮説に至った。
ワークフローは3段階で、(1) GitHub イシューに Claude Code Action が反応してデザインルールを生成・レビュー・コミットする半自動更新、(2) ルールをすぐ呼び出せる AI チャットボット、(3) ルールとコンポーネントをナレッジベースにした MCP サーバーでの UI 自動生成（社内検証中）。
導入により、属人的で負荷の高かったデザインルール文書化が2〜3ラリーのやり取りでほぼコストゼロになり、デザイナーが素早くルールを確認できるようになった。
UI デザインを誰でもできるようにした先に、デザイナーは未検証のデザイン領域（ディスカバリーや新規事業立ち上げ等）へ注力するのが狙いで、LLM による UI 自動生成のラストワンマイルは「デザインの意志込め」だと主張する。
