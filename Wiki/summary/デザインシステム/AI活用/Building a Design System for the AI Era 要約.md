# Building a Design System for the AI Era 要約

ソース: [[Building a Design System for the AI Era]]

インタラクションデザイナーの筆者が、AI にデザインシステムを制約として与えて production 水準のデザイン案を生成させる「compound design system」の構築過程を記録した実践録。
Google の DESIGN.md プロトコルを起点に、ジュニアデザイナーへの指導経験を援用して制約を「デザイントークン（視覚的原子）・デザイン言語（判断基準）・デザインパターン（シナリオ雛形）」の3層に整理した。
検証ツールには Stitch（Google 色が混入）や Claude Design（内部ワークフローが補正しすぎて評価不能）を退け、指示に忠実な Claude Code を採用した。
Stable Diffusion のモデル学習経験から DESIGN.md を「反復可能なルールモデル」と捉え、過学習（1ページ事例への過剰適合）と学習不足（曖昧な形容詞による自由すぎる出力）を診断しながら v0.9 まで反復し、一貫したスタイルのページ生成を実現した。
結論として、AI 時代のデザインシステムは成果物ではなく「実行可能な制約システム」であり、人と人の協働だけでなく人とモデルの協働問題を解くものになる——デザイナーは暗黙の経験則をトークン・言語・パターンに翻訳する明晰さを要求される、と主張する。
