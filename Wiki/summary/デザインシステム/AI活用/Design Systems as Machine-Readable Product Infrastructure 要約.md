# Design Systems as Machine-Readable Product Infrastructure 要約

ソース: [[Design Systems as Machine-Readable Product Infrastructure]]

デザインシステムは受動的な参照文書から、AI エージェントが直接クエリする「機械可読なプロダクトインフラ」へ構造的に変わるべきだと論じる記事。
機械可読とは出力（ボタンや色見本）ではなくロジック——なぜその決定がなされたか、どこで使えるか——を構造化形式で公開することであり、セマンティックトークン（`color-feedback-error`）がその前提になる。
MCP 統合により AI コーディングツールは生成時に正しいトークン・パターン・制約を取得でき、訓練データ由来の「もっともらしい近似」による design-to-code ドリフトを防げる。
アーキテクチャ要件として、セマンティックトークン層・機械可読な決定文書・明示的な使用制約・バージョン付きクエリ可能 API の4つを挙げる。
ガバナンスも人間の貢献者向けから「AI 消費者」向けの層が必要になり（どの部分が AI クエリに耐える安定度か、AI 生成物の検証手順、トークンスキーマと MCP サーバー設定の所有権）、DS をデータベーススキーマや API 契約と同じ厳密さで扱うチームが次の局面を制すると結論づける。
