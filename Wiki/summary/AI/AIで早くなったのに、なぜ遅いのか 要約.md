# AIで早くなったのに、なぜ遅いのか 要約

ソース: [[AIで早くなったのに、なぜ遅いのか]]

GitHub Copilot ユーザーの 88% が生産性向上を実感する一方、LeadDev 調査では大きな向上を報告したエンジニアリングリーダーは 6% のみ、McKinsey 調査でも約 80% の企業が大きな成果を得ていないという、個人と組織のギャップを起点に論じる記事。
原因として、一見良さそうだが実際には使えない AI 生成物「Workslop」がレビュー・調整・認識合わせのコストを増大させている点を挙げ、スピードと量が評価される文化では Human in the Loop も機能しにくいと指摘する。
真の課題は「価値を生む使い方」と「見てくれだけの使い方」を区別できないことであり、「良いとは何か」「人間はどう関わるか」「何が差し戻し基準か」の解像度を上げ、利用パターンと価値を結びつけるフィードバックループが必要だと主張する。
筆者自身は Claude Project を使った個人レベルの実験で、生成と改善のループを回しながら暗黙知の明文化を進めている。
結論として、効率化を漠然と語らず、決定時に必要な最低限の「良さ」を明らかにすることが AI との関係を変えるとまとめている。
