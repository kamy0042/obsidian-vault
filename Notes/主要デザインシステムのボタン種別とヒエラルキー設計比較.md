主要9つのデザインシステム（Material Design 3 / Carbon / Lightning / Polaris / Fluent 2 / Atlassian / Spectrum / Primer / Ant Design）のボタンコンポーネントについて、種類とヒエラルキー設計を比較した調査メモ。

# バリアント一覧（強調度の高い順 → 低い順）

| システム | バリアント |
|---|---|
| **Material Design 3** (Google) | FAB → **Filled** → **Filled Tonal** → **Elevated** → **Outlined** → **Text** ／ Iconボタン別系統 |
| **Carbon** (IBM) | **Primary** → **Secondary** → **Tertiary** → **Ghost** ／ Danger は Primary/Tertiary/Ghost の3段階を別途用意 |
| **Lightning** (Salesforce) | **Brand** → **Outline Brand** → **Neutral** → **Base**（テキストのみ） ／ 意味系: **Destructive** / **Destructive Text** / **Success** / **Inverse** |
| **Polaris** (Shopify) | `variant`: **primary** → **secondary** → **tertiary** → **plain** → **monochromePlain** ／ `tone`: **success** / **critical** が直交 |
| **Fluent 2** (Microsoft) | **Primary** → **Secondary**(default) → **Outline** → **Subtle** → **Transparent** |
| **Atlassian** | **Primary** → **Default** → **Subtle** → **Link** / **Subtle Link** ／ 意味系: **Warning** / **Danger** |
| **Spectrum** (Adobe) | `variant`: **Accent**(default) / **Primary** / **Secondary** / **Negative** × `treatment`: **Fill** / **Outline** の組合せ |
| **Primer** (GitHub) | **Primary** → **Default**(secondary) → **Outline** → **Invisible** ／ 意味系: **Danger** |
| **Ant Design** | `type`: **Primary** → **Default** → **Dashed** → **Text** → **Link** ／ 修飾: **danger** / **ghost** |

# 共通する設計パターン

## 1. 4〜5段階の強調レベル

ほぼ全システムが「最強調 / 標準 / 控えめ / 最小（透明・テキスト）」を持ち、間に「Outline」相当を挟むかどうかで枝分かれ。

- 5段階派（MD3, Carbon, Polaris, Fluent 2, Ant Design）
- 3〜4段階派（Atlassian, Primer, Lightning）

## 2. 意味（Semantic）を直交軸で扱う

強調度とは別に「Danger / Destructive / Critical / Negative」「Warning」「Success」を直交プロパティで持たせるのが主流。

- 直交モデル: **Polaris**（`tone`）, **Spectrum**（`variant`軸）, **Ant Design**（`danger` flag）
- 各強調レベルに別バリアントを用意: **Carbon**（Primary/Tertiary/Ghost Danger）, **Lightning**（Destructive / Destructive Text）

→ 直交モデルは API がスケールしやすく、強調度別に複数用意するモデルは命名で意図が伝わりやすい、というトレードオフ。

## 3. 「1画面に Primary は1つ」原則

Ant Design・Primer・Fluent 2 が明文化。MD3 も "important, final actions" と限定。

## 4. ペアリングの推奨

- **Carbon**: Primary と Secondary は必ずペア（Secondary は単独使用不可、Cancel/Back 専用）。Primary/Secondary/Tertiary を同一グループで混在させない。
- **Atlassian**: Primary + Subtle / Primary + Link が定番ペア。3つ以上なら Primary → 標準 → Link の順。
- **Fluent 2**: Minor アクションが多い時は全部 Outline/Subtle/Transparent に揃える。
- **Ant Design**: 3アクション以上なら Dropdown 化を検討。

## 5. ヒエラルキーの「中間段階」の作り方が分かれる

中強調を何で表現するかが各社の個性:

- **塗り**で中強調: MD3 Filled Tonal, Lightning Brand Outline
- **枠線**で中強調: Carbon Tertiary, Fluent 2 Outline, Primer Outline, Ant Design Dashed
- **無背景＋ホバー時に背景**: Atlassian Subtle, Fluent 2 Subtle, Carbon Ghost, Primer Invisible

# ヒエラルキー設計の3つの軸

各社の差分はこの3軸の取り方に集約される:

1. **強調軸**（visual weight）: 段階数 4 or 5 ／ 中強調を Tonal / Outline / Subtle のどれで埋めるか
2. **意味軸**（semantic）: 直交プロパティ vs バリアント分割
3. **形状軸**（shape/treatment）: Spectrum のように `treatment` を独立軸に取るか、バリアント名に内包するか

# 直交モデル詳説

ボタンのプロパティを **強調度（hierarchy）** と **意味（semantic / tone）** という独立した2軸に分解し、それぞれを別の prop で指定する設計。N段階の強調 × M種類の意味 = N×M バリエーションを **N+M 個の prop 値** で表現できる。

## 具体例 1: Polaris（Shopify）

```tsx
<Button variant="primary" tone="critical">削除</Button>
<Button variant="secondary" tone="critical">削除</Button>
<Button variant="primary" tone="success">承認</Button>
<Button variant="plain" tone="critical">削除</Button>
```

- **`variant`**（強調軸）: `primary` / `secondary` / `tertiary` / `plain` / `monochromePlain`
- **`tone`**（意味軸）: `success` / `critical` ／ 未指定 = neutral

5強調 × 3意味 = 15通りを **5 + 3 = 8個の値** で表現。

## 具体例 2: Adobe Spectrum

```tsx
<Button variant="accent" treatment="fill">保存</Button>
<Button variant="accent" treatment="outline">保存</Button>
<Button variant="negative" treatment="fill">削除</Button>
<Button variant="negative" treatment="outline">削除</Button>
```

- **`variant`**（意味軸）: `accent` / `primary` / `secondary` / `negative`
- **`treatment`**（強調軸）: `fill` / `outline`

意味と表現を完全に分離。「Negative の Outline」のように、**意味は変えずに視覚強度だけ落とせる**のがポイント。

## 具体例 3: Ant Design

```tsx
<Button type="primary">確定</Button>
<Button type="primary" danger>削除</Button>
<Button type="default" danger>削除</Button>
<Button type="text" danger>削除</Button>
```

- **`type`**（強調軸）: `primary` / `default` / `dashed` / `text` / `link`
- **`danger`**（意味軸 / boolean）: 危険操作フラグ

意味側を boolean に切り詰めた割り切り型。表現力は劣るが API が極小。

## 非直交モデル（バリアント分割）との対比

Carbon は同じ事を **すべて variant 名で表現** する:

```tsx
<Button kind="danger">削除</Button>           // primary 相当の Danger
<Button kind="danger--tertiary">削除</Button>  // tertiary 相当の Danger
<Button kind="danger--ghost">削除</Button>     // ghost 相当の Danger
```

- prop は1個（`kind`）だが、値が **強調 × 意味の積** だけ存在する。
- Danger × {Primary, Tertiary, Ghost} の3つは定義されるが、**Danger × Secondary は意図的に存在しない**（Secondary はキャンセル専用なので意味的に不整合）。

→ 直交モデルは「組合せが全て成立する」前提、非直交モデルは「**成立しない組合せを表現できなくする**」のが利点。

## 直交モデルの利点

**1. API が線形に増える**
意味軸に色を1つ足しても prop 値が1つ増えるだけ。バリアント分割だと「強調レベル × 新色」の数だけ追加が必要。

**2. ロジック側で意味と強調を独立に決められる**

```tsx
// アクションの危険度はビジネスロジックで決まる
const tone = action.isDestructive ? 'critical' : undefined;
// 強調度はレイアウト上の位置で決まる
const variant = isPrimaryCTA ? 'primary' : 'secondary';
return <Button variant={variant} tone={tone}>{label}</Button>;
```

2つの関心事が別の値に分離されるので、**呼び出し側で組み立てやすい**。

**3. デザイントークンへの落とし込みが綺麗**
強調軸 = surface/border の段階トークン、意味軸 = semantic color トークン、と命名空間が一致する。

## 直交モデルの欠点・落とし穴

**1. 不正な組合せが表現可能になってしまう**
`variant="plain" tone="success"` のような「ほぼ見えない成功ボタン」が型としては合法。型レベルで弾けない。

→ 対策: `variant` ごとに許可する `tone` を絞る discriminated union、または Storybook / lint で禁則を明示。

**2. 「同じ意味」を複数の API 形で書けてしまう**
Spectrum の `variant="negative"` と、`tone="critical"` を別の意味軸でやるシステムでは混同が起きる。

**3. 一部組合せだけデザインが特殊になりがち**
「Primary の Critical だけは色が反転する」など例外が出ると、直交の純粋性が崩れて結局 variant 名に内包し直す事になる。Carbon が直交を採らずに `danger--*` で分割しているのはこの予防。

**4. ドキュメントが組合せ表になりがち**
ユーザーから見ると「どの組合せが推奨か」が分かりづらく、結局 Polaris のようにドキュメントで「primary + critical は破壊的な確定アクション」とパターン化して提示する必要が出る。

## 軸の選び方の指針

| 状況 | 推奨モデル |
|---|---|
| 意味色が neutral / danger だけの最小構成 | **boolean 直交**（Ant Design 型）で十分 |
| success / warning / info など意味色が3つ以上 | **多値 prop の直交**（Polaris 型） |
| 「Outline 版が全 variant に欲しい」など表現軸が独立 | **2軸完全直交**（Spectrum 型） |
| 不正な組合せをデザイン側で潰したい / 例外が多い | **バリアント分割**（Carbon 型） |
